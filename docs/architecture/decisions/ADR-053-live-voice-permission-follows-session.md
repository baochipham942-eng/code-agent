# ADR-053：通话态权限档跟随会话选择，不再抬严到 readOnly

- 状态：accepted
- 日期：2026-07-29
- 取代：D4 Live 语音抬严（2026-07-26 决议，见 `clampLiveVoicePermissionMode` 的旧顶注）

## 背景

实时语音上线时定了 D4「通话态抬严」：会话档只要有免确认（`bypassPermissions` /
`acceptEdits` / `default`），一进通话就钳到 `readOnly`，写文件和跑命令一律逐次确认。

理由写得很清楚：

> 通话时用户手不在键盘、眼睛不在 diff 上，口述「好的」既没有具体对象也没有可回看的痕迹，
> 不能替代权限卡点击。

## 为什么推翻

**这条理由和它的效果方向相反。** 抬严的前提是「用户点不了确认」，抬严的效果却是
「弹更多确认让他点」。

2026-07-29 真机实录坐实了：用户在通话里说「帮我在当前目录建个文件，a.txt，内容写一二三」，
会话档被钳到 `readOnly`，执行侧把这件活拆成三步——

| 时刻 | 动作 | 是否要确认 |
|---|---|---|
| 05:12:10 | 派活 | — |
| 05:12:23 | **用户挂断** | — |
| 05:13:45 | `ls -la ~` | 要 |
| 05:13:57 | `Write notes.md` | 要 |
| 05:14:04 | `ls -l notes.md` | 要 |

三张审批卡**全部在挂断之后**才弹出来。用户对着一个凭空出现的紫色大框点了三次，
其中两次是只读的 `ls`。

- **安全上什么都没挡住**：他不知道这是哪来的、也没有拒绝的依据，只能全点允许。
  逐次确认在这里退化成一个纯仪式。
- **体验上把语音这条链堵死在第一步**：一件最小的活要 2 分钟 + 3 次点击，
  后续所有真机验收都走不到第二步。

同时，D4 当初防的「无声改东西」这个前提，在发言人协议（W6，#798）之后已经不成立：
每件活的结论会被念出来，执行过程折叠在会话里的任务卡上，失败留痕独立落库。

## 决议

**通话态权限档跟随会话自己的选择。** 用户选 `acceptEdits` 就是已经拍过板了，
系统不该趁他打电话替他改回去。原来靠「事前逐次点头」承担的保障，改由**事后可追溯**承担。

**唯一保留的底线：`bypassPermissions` → `acceptEdits`。**

这一条不是不信任用户，是**语音独有的新风险**：ASR 会听错。同日实录里
「a.txt」被听成「a点text」，最后落盘的文件叫 `notes.md`——用户说的和系统听到的
根本不是一回事。文本模式下打错字用户自己看得见，语音下看不见。
`bypassPermissions` + 听错 = 零确认执行一条他没说过的命令。

同款钳制在无人值守会话已有先例（`clampUnattendedPermissionMode`），照抄那个口径，不自创。

子 agent 链同一决议：只压掉「四类操作全自动批准」的 `ci` preset，其余跟随。

## 这个决议押在什么上

它把保障从「事前逐次点头」换成「事后可追溯」，所以**可追溯这条链必须是完整的**。
已经在位的：

- 发言人协议把每件活的结论用第一人称念给用户（W6-1/2/3）
- 执行过程折叠进会话里的任务卡 + 署名（W6-5）
- 失败留痕独立落库，挂断后仍可复查（G1）

**已知缺口**：run 在挂断之后才落地时，发言人协议不念（挂断即断），只剩会话里那张任务卡——
用户得主动打开那条会话才看得到。这个缺口必须补上，否则本决议真的会开一个
「无声改东西」的洞。补法见后续工单（挂断后落地的活要有用户找得到的通知）。

## 连带变化

`readOnlyDenialError` 的通话专用文案分支已删。它当初存在是因为「请切换会话权限档」
在钳档下是假话（档是通话钳的，切了没用）；现在通话中还处在 `readOnly` 只有一种可能——
用户自己选的，那句话恰恰是真话，也是他唯一该听的建议。留一条永远走不到、
且内容已经变假的分支，比没有更糟。

**通话态标记（`isLiveVoiceSession`）本身不废**：它现在还有第二个消费者——
交互式工具收窄（`requiresUserPresence`，通话里 `AskUserQuestion` 一律拿掉），
那条同样必须罩住「挂断后 run 还在跑」的窗口。所以票据生命周期原样保留。

## 门

`tests/unit/permissions/liveVoiceClamp.test.ts` 的旧不变量「通话态一律弹确认」
改写成「通话前后判定一模一样」，判据仍打在真实审批决定上，不打在档位字段——
档位从来不是放行的唯一闸门（`permissionClassifier` 的 W1 规则与档位无关，
2026-07-26 那个洞就是这么漏的）。

变异验证：拆掉 `bypassPermissions` 底线 → 3 条红；退回旧的一律钳 `readOnly` → 6 条红。
