# ADR-053：会话三层分类——快速对话 / 独立项目 / 协同空间（1:1 升级形态）

- 状态：已采纳（2026-07-29 产品负责人拍板：协同空间与项目 1:1）
- 日期：2026-07-29
- 相关：批P 项目协作空间（项目列表 + 空间页）、ADR-035（@neo 跨会话续接）、P1 云壳（项目云身份 + 成员邀请）

## 背景

在批P（项目列表 + 项目协作空间）落地时，产品负责人提出：历史会话需要有明确的三层归属分类——独立项目、协同空间、快速对话。此前数据模型只有两层事实：会话要么有 `project_id`（项目由工作目录派生，`ensureProjectForWorkspace`），要么没有（侧栏「快速对话」组）。「独立项目 vs 协同空间」的区分不存在。

分叉点：协同空间与项目是 1:1（项目升级成空间）还是 1:N（一个空间挂多个项目）。

## 决策

**三层定义（锚定数据模型，不是纯文案分类）：**

| 层 | 定义 | 数据锚点 |
|---|---|---|
| 快速对话 | 无项目归属的会话，不继承项目上下文 | `session.project_id = null` |
| 独立项目 | 本地项目（工作目录派生），单人 | `projects` 表现有实体，无云身份 |
| 协同空间 | **项目的升级形态**：绑定云身份 + 有成员后，该项目即协同空间 | P1 云表（项目云身份 + `project_members`）落地时打标 |

**协同空间 : 项目 = 1:1**（对标 WorkBuddy：项目本身就是空间）。不引入「一个空间挂多个项目」的中间容器层——邀请、权限、会话归属都停留在项目粒度；组织/团队层如有需要属 P2 之后的独立决策。

**会话归属机制不变**：`session.project_id` 就是唯一归属通道。协同空间页内发起的会话（任务 tab 续接、底部输入框）天然挂当前空间；每个空间的动态/任务/资产 tab 按 `project_id` 作用域聚拢。项目升级为协同空间不迁移任何会话数据。

## 影响

- **P0（批P）零改动**：项目列表/空间页用的就是既有项目实体。
- **P1（云壳）**：项目绑定云身份后即视为协同空间；侧栏与项目列表加云标区分「独立项目 / 协同空间」；侧栏分区顺序 = 协同空间 → 独立项目 → 快速对话。
- **命名约束**：UI 文案与代码注释统一用「快速对话 / 独立项目 / 协同空间」三词；「项目」在无云身份语境下即独立项目。

## 否决项

- 1:N（空间挂多项目）：多一层容器导致邀请粒度、权限继承、会话归属全部多一层设计，且 WorkBuddy 对标形态不需要。
