# ADR-059：文字前台恢复写工具——「按工具名一刀切」判据的第三次修正

- 状态：accepted（2026-08-18 产品负责人拍板通过，口径无修改）
- 日期：2026-08-18
- 关联：[ADR-054 会话=指挥台](./ADR-054-session-as-command-center.md)（不推翻）、
  [ADR-056 前台放开只读工具](./ADR-056-command-center-foreground-read-tools.md)
  （修订其「不覆盖的场景：改一下这个文件仍然只能派活，这是设计意图」一条）
- 落地单：`N-FGWRITE`

## 背景

ADR-054 立下的原则是：前台工具策略只允许**短时、低副作用**操作，耗时工作进入后台槽。
原则没有被推翻，三次出现偏差的是手写工具名 allowlist：

| 次序 | 当时实现 | 真机后果 |
|---|---|---|
| 一 | 5 元组，连 `Read` 都不给 | 2026-08-06 验收失败；Windows 测试者首条读请求触发 5 轮追问和 3 次 300 秒超时 |
| 二 | 放回四个只读工具，漏登记 `spawn_agent` | 用户点名角色时角色从未真正调起，RoleWriteBack 零日志 |
| 三 | 写入仍然只能派活 | 简短的文字文件修改被转成后台任务 |

三次偏差形状相同：实现按工具名枚举，原则按时长与副作用判定；人工清单持续比原则更窄。

## 判断依据

### 文字与语音的占用成本不同

ADR-054 的架构参照是语音 agent。通话中 agent 被任务阻塞十秒会造成没有回应的产品事故，
因此语音前台不能被占用。文字场景下，用户等待几秒看到标题直接改完，优于收到「已安排，稍后告知」。
两个通道继续共享产物主轴、任务账本、可中断与可回放能力，但无需共享相同的前台工具宽度。

### 前台直接写文件属于产出

「聊天式 agent 价值太低」针对只会回复、不能产出。直接完成短小文件修改本身就是产出，
用这条理由移除文字前台写能力属于误伤。

### 写路径已有安全前提

基线 `origin/main@9181aec1` 已包含 PR #1244 的 read-before-write、`read_digest` 校验与
按 `sessionId:agentId` 隔离的排他锁，以及 PR #1243 的声明式安全元数据。
前台恢复发起能力不改变 folder-trust、权限档与审批链路。

## 决策

**文字通道前台恢复满足「短时 × 低副作用」的文件写工具；语音通道不变。**

- 文字桌面与 web 路径从工具 schema 的 `allowInTextForeground` 声明生成前台工具面。
- `Read` / `Grep` / `Glob` / `ListDirectory` 与短小文件修改所需的 `Write` / `Edit`
  由各自 schema 声明适用。
- `Append` 面向多段生成且缺少同等级 read-before-write；`notebook_edit` 缺少同等级读记录校验与
  排他锁，因此本次普查判定不进入前台。
- Bash、命令执行、联网、需要审批的重活、多步骤执行，以及写报告、做网页等生成级长任务继续进入后台槽。
- 语音继续使用独立窄工具集 `task_status` / `get_current_file_summary` /
  `capture_screen_context` / `delegate_task` / `steer_task` / `cancel_task` / `get_current_time`；
  通话中写文件仍由 `delegate_task` 派后台。

### 判据换代

不再维护文字前台工具名 allowlist。工具在自己的 schema 中用 `allowInTextForeground: true`
声明单次调用满足文字前台「短时 × 低副作用」边界，前台按声明过滤，禁止按工具名推断。
新增工具必须在 schema 评审时明确判断；存量工具的逐项判断与不适用理由记录在本单证据档。

## 不做 / 边界

- 不推翻 ADR-054；文字会话仍是指挥台，耗时工作仍进入后台槽。
- 不放开 Bash、命令执行、联网或需要审批的重活。
- 不改语音通道。
- 不改权限与审批。放开的是「模型能不能发起」，不是「能不能绕过审批」。
- `skillBoundaryScope.ts` 的严格 skill 工具收窄由 skill 自己的 `allowedTools` 激活，前提与文字
  指挥台不同，继续保留其「流程设计，不是权限问题或环境故障」说明。

## 后果

- 「改一下这个文件」可在文字会话前台直接完成。
- ADR-056 原文「不覆盖的场景：改一下这个文件仍然只能派活，这是设计意图」被本 ADR 修订。
- 指挥台提示词与 `delegate_task` 描述不再把短小文件写请求一律路由到后台。
- 工具面与路由说明变化，`PROMPT_VERSION` 必须 bump。
- read-before-write 的典型链路为模型发起 `Read`、模型发起 `Edit`/`Write`、模型回复结果，
  需用真机数据复核 8 次迭代上限。

## 验收

1. 文字会话说「把这个文件的标题改成 X」，前台直接修改并回复完成，不派活，也不使用环境禁用类措辞。
2. 语音通话中同一句仍调用 `delegate_task`。
3. 负例证明前台写仍经过 folder-trust、权限档与审批链路。
4. 移除写工具的前台声明后，文字直接写用例失败；验证后还原变异。
5. 证据档列出全部存量工具及每项适用性理由。
