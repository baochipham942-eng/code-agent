# v0.33.0 用户体验合同（cowork 视角）

> 定位：Agent Neo 是 cowork 人机协作产品，产物（deliverable）是主轴，不是 AI 编程助手。
> 本文按这个定位组织 v0.33.0 的用户可见体验合同：用户在协作中**读得动、看得清、信得过**——
> 读得动（长会话阅读）、看得清（它做了什么、在干什么）、信得过（审批与拒绝说真话）。
> 本文只写用户可见合同，不重复架构实现；事实源见下。

## 1. 长会话阅读与回底

**体验目标**：协作会话攒到几百轮之后，历史仍然"读得动"——往上翻不跳、搜索跳转看得到目标、流式输出时回底可靠。阅读是 cowork 产品里用户停留时间最长的动作。

### 入口与状态

- 会话正文是 react-virtuoso 虚拟列表（`src/renderer/components/features/chat/TurnBasedTraceView.tsx`，由 `src/renderer/components/ChatView.tsx:809` 挂载）。
- 上滚离底时浮出「回到底部」按钮，贴底隐藏；文案在 `src/renderer/i18n/chatTranscript.ts:179-186`（`jumpToBottom: '回到底部'`、`loadingOlder: '加载更早的消息…'`）。

### 交互合同

- **翻历史不锚漂**：往上 prepend 历史时，用户当前看的轮保持原位（`TurnBasedTraceView.tsx:237/248` 的 prepend 锚点与像素级补偿）。
- **重内容延迟渲染，但轮壳永远可测量**：只有嵌套重内容（tool-card / code-block / 超 800 字符长文本）走 `content-visibility` defer（`src/renderer/utils/turnContentVisibility.ts`）；整轮壳不再写死占位高度——v0.33.0 之前正是整轮 defer 导致虚拟列表总高算错、锚点漂 469px。
- **搜索跳转目标居中可见**：搜索命中轮 `align: 'center'` 落视口中部，不被首帧落底抢走。
- **回底是显式结算，不是一次性滚动**：点击「回到底部」走 `scrollToIndex(align:'end')` + 60 帧 rAF 结算循环把 `scrollTop` 钉到 `scrollHeight`（`TurnBasedTraceView.tsx:895-940`），覆盖旧的手势抑制并恢复跟随。
- **流式跟随有礼貌**：用户上滚手势暂停跟随 800ms 后自动恢复（`USER_SCROLL_FOLLOW_REENGAGE_PAUSE_MS`），流式期间不重 parse 已完成块（块级 memo，`src/renderer/components/features/chat/MessageBubble/streamingMarkdownBlocks.ts`），长会话下每 tick 只重算尾块。

### 异常与恢复

- 整轮 defer 回归（有人重新给轮壳写死占位高）会被 `turnContentVisibility.tiers` 测试直接拦红——见验收锚点。
- 流式结束后的 settle 保证最终贴底；prepend 锚点补偿失败的最坏结果是视觉抖动，不丢消息。

### 当前边界

- 反向变异证明（只翻修①/只翻修②各自报红）是 PR #1257 期间的手工变异 + 重跑 smoke，**未沉淀为可重复执行的自动化**；仓内承重的是单测断言 + smoke 阈值门。
- 长会话滚动正确性挂上每个 PR 的 CI 门是 post-tag `#1260`，v0.33.0 里这门只在发版证据闸里。

### 验收锚点

- 已实现：`tests/renderer/components/turnBasedTraceView.test.ts`（`:684` 显式回底覆盖手势抑制并恢复跟随；`:146` prepend 像素级恢复；`:552` 流式结束 settle 到底；`:648` 搜索命中居中）；`tests/renderer/components/turnContentVisibility.tiers.test.tsx:44`（**任何状态轮壳不得输出 `data-deferred-content="turn"`**，整轮 defer 回归即红）；`tests/renderer/components/streamingMarkdownBlocks.test.tsx`（块级 memo 只重渲尾块）。
- 已验证（real-runtime）：`scripts/perf/long-session-browser-smoke.ts` 七门（500 轮交互 / 锚漂 ≤16px / 用户滚动保位 / 流式回底 / 搜索可见 / 长任务 / 内存），fail-closed（`passed:false` 退出码 1）；最近一次证据 `docs/perf/long-session-gold-latest.json`（darwin/arm64，锚漂 0.344px、距底 0px、搜索可见）。
- 未验证：无真机人工验收记录；上述 real-runtime 证据是 headless Chrome，不等同用户实机手感。

## 2. 会话检查器与轮内追踪

**体验目标**：cowork 的信任前提是"它到底替我做了什么"可回看。检查器把每一轮里实际调用了哪些能力、按什么顺序、结果如何摆出来；进程意外退出后，已经 flush 的记录前缀仍可读。

### 入口与状态

- 入口在 TaskPanel 右栏的 `inspector` tab（`src/renderer/components/TaskPanel/index.tsx:44`），组件 `SessionInspector`（`src/renderer/components/TaskPanel/SessionInspector/index.tsx`），两层视图：层 1 轮行时间线，层 2 单轮 DevTools（manifest、per-call 推理分卡）。
- 聊天流内每轮轮头有结果印章徽标（`src/renderer/components/features/chat/TurnOutcomeBadge.tsx`）：「完成有据 / 自称完成」——区分"有证据的完成"与"模型自称完成"，这是 cowork 产品对"交付可信度"的核心表达。
- 文案：`src/renderer/i18n/sessionInspector.ts`（印章三态、组装面板「未记录」、降级标注等，zh/en 全量）。

### 交互合同

- **活会话可追踪**：进行中的轮以"活行"接回 tail 增量（轮询 2.5s），轮 settle 后原地转为常规行，不重复渲染。
- **读不到就是读不到**：trace 客户端任何失败一律返回 null 走空态（`src/renderer/services/traceLedgerClient.ts`），绝不臆造账本内容；无 manifest 的轮明示「不可回放」，flush 降级（`degraded`）如实标注。
- **印章来自证据而非自述**：`turn_outcome` 裁决（`src/host/agent/runtime/turnOutcomeStamp.ts`）里 goal gate / voice 证据优先，无证据的 completed 只能是 `self_claimed`。

### 异常与恢复

- **崩溃可读**：轮内事件增量落盘（8 事件 / 2s 节流，`src/host/agent/runtime/turnTrace.ts:24-25`），进程 SIGKILL 后已 flush 前缀可读；坏行跳过并计数（`skippedLines`），不让一行坏 JSON 毁掉整本账。
- **flush 失败 fail-closed**：只 warn 并把未落盘 manifest 标 `degraded`，不抛、不假装成功。
- **读侧防穿越**：sessionId 路径穿越（`../escape`）与越界 cursor 一律拒绝（`src/host/app/traceReadService.ts`）。

### 当前边界

- 检查器只能读已 flush 的事件前缀，崩溃前未落盘的内存事实不可恢复（SPEC §5）。
- trace 文件 rotation/retention 不做（`traceReadService.ts:76` TODO）。
- 补偿登记（#1219）只覆盖发射类工具（file write/append、mailSend），`sufficiency` 恒为 `'unreviewed'`——充分性审查刻意留空。
- 能力单元运行时（#1218）当前只允许 `skill` 单元；补偿是可执行恢复钩子，不是跨服务事务（SPEC §5）。

### 验收锚点

- 已实现：`tests/unit/agent/turnTrace.test.ts`（8 事件 / 2s 节流、flush 幂等、flush 失败标 degraded 不抛）；`tests/integration/agent/turnTraceCrashReadable.test.ts`（**崩溃可读证明**：子进程 SIGKILL 后 inference/tool_dispatch 已落盘、半行坏 JSON 跳过计数）；`tests/unit/host/app/traceReadService.test.ts`（路径穿越 / 越界 cursor 拒绝）；`tests/renderer/components/sessionInspector.model.test.ts` 与 `sessionInspector.view.test.tsx`（活行 settle 原地转常规行、非法 verdict 置空不臆造）；`tests/unit/agent/turnOutcomeStamp.test.ts`（无证据 completed → self_claimed）。
- 已验证（fault-injection）：崩溃可读走的是真实子进程 + 真实文件系统的故障注入（SPEC §6 标 fault-injection）。
- 未验证：检查器无 e2e 用例；`scripts/acceptance/turn-trace-crash-readable.ts`（真实 webServer + 真实模型的 headless 验收脚本）存在但**未挂进任何 npm script，仓内无执行留档**；SPEC §6 把检查器行标为 `static-contract`。无真机验收记录。

## 3. 语音轮流说话与通话审计

**体验目标**：语音通话是最接近"同事感"的协作面。目标是它**不抢话**（你停顿思考时它不接茬）、**听得准**（挂断/转向意图不误判）、**可回溯**（每通说话/打断/审批/结局留时间线）。

### 入口与状态

- 通话入口：composer 内 `LiveVoiceButton`（不可用时降级为「点我配 key」引导态）+ `VoiceStartDialog` 开场确认；通话中状态走 `VoiceChrome` 星球七态（设计系统 §4）。
- 审计入口：侧栏会话行右键菜单的「语音审计」（`src/renderer/components/Sidebar.tsx:887`、`src/renderer/components/SessionActionsMenu.tsx:414`），弹窗 `VoiceAuditDialog` 按通话列时间线（说话 / 打断判定 / SAY-DO / 派单 / 审批 / 结局 / 录音 / 费用），支持导出 Markdown。
- 审计三态文案（`src/renderer/i18n/voiceAudit.ts`）：「查过了 · 无事件」与「无法查询」是两种状态——查过没有和查不了不混为一谈。

### 交互合同

- **不抢半句话**：打断走三层判定链——L2 证据层（`voiceInterruptEvidence.ts`，burst/earlyOverlap/指向性 → weak/medium/strong）→ L3 语义出口（`voiceTurnTaking.ts`）。附和（"嗯/好的"）不取消发言；**非 strong 证据不兜底取消**（`voiceTurnTaking.ts:79-81`）。
- **它可以说"这轮我不接"**：`ignore_turn` 工具出口让模型在噪声轮静默收尾，不进 dispatch、不触发后续响应（`src/host/services/voice/voiceTools.ts:142,226`）。
- **歧义指令不派发**：接待层检出歧义截断信号（数字撞车、悬空量词，`voiceRouting.ts:114`）时，本轮 prompt 明确禁用 delegate/steer——拿不准就不动手，这是 cowork 场景的 fail-closed。
- **审批跨断线存活**：renderer 断线重连后，待确认审批快照重新下发并入队判重，用户不用重来（`listPendingRequests()` 快照 + `usePermissionQueueEffects` 去重）。

### 异常与恢复

- **SAY-DO 守卫故障保持关闭**：分类器 rate_limited / server_error / empty_response / invalid_contract_output 四种故障一律 `no_intervention`，不触发确定性补派（`src/host/services/voice/voiceSayDoGuard.ts`）——守卫自己病了不乱治。
- **审计永远给得出回答**：每段 ok / none / unavailable 三态，聚合失败不吞（`src/host/services/voice/voiceCallAudit.ts`）。
- 打断遥测走 shadow 采样，只带布尔/数值不带字幕原文。

### 当前边界

- direct transport 侧真 OpenAI adapter 未落地，v0.33.0 只跑了 qwen-omni relay 形态（`voiceTransportContract.test.ts` 注释）。
- L2 判定阈值依赖 2026-08-16 一次真机分布采样，无持续回归的真机门。
- SPEC §5：语音自动化覆盖不等于所有设备、麦克风、网络和真实账号场景已完成发布级真机验收。

### 验收锚点

- 已实现：`tests/unit/voiceInterruptEvidence.test.ts`（电视噪声 → weak、真人指向请求 → strong）；`tests/unit/voiceTurnTaking.test.ts`（附和不取消、真打断取消、陌生声纹 speakerGated）；`tests/unit/voiceSayDoGuard.test.ts`（**fail-closed 核心**：四种分类器故障 → `no_intervention`）；`tests/unit/voiceSpeakerProtocol.test.ts:409-422`（歧义截断分类 + prompt 禁用派活）；`tests/renderer/components/voiceAuditDialog.test.tsx`（三态 section、timeline fetch、Markdown 导出）；`tests/renderer/hooks/usePermissionQueueEffects.test.ts`（重连审批快照恢复/判重）；`tests/e2e/voice-ux-display.spec.ts`（费用空态等文案人话化）。
- 未验证：SPEC §6 本行标 `hermetic-protocol`；docs/ 内无真机通话验收记录（#1185 commit 引用的验收件在未入库私档，当前不可核实）。Intel x64 VAD 采集差异说明是 post-tag `#1259`，不属于本版。

## 4. 逐轮联网搜索与模型能力自动识别

**体验目标**：联网是逐轮的协作选择，不是全局开关——这一轮不想让它上网就关掉。模型能力（联网、深度思考、协议家族）由系统自动识别，用户不用手工配。

### 入口与状态

- **逐轮开关**：模型选择弹窗内的「联网搜索 开/关」两格按钮（`src/renderer/components/StatusBar/SearchToggleSection.tsx`，由 `ModelSwitcher.tsx:1015` 渲染）；当前模型不支持联网且未配外部搜索源时置灰并给原因提示（`src/renderer/i18n/zhSettingsModels.ts:158-162`）。
- **搜索源凭据**：设置页搜索 tab（`src/renderer/components/features/settings/tabs/SearchSettings.tsx`）配智谱 / MiniMax 密钥，并可选「自动 / 智谱 / MiniMax」外部源。
- **能力自动识别**：模型能力收敛到声明矩阵（`src/host/model/modelCapabilityMatrix.ts`）：协议家族、搜索模式、interleaved thinking、端点形态各自声明，DeepSeek / qwen 百炼 / 中转 provider（方案 D）按声明走；`deepseek-v4-flash` 摘掉「未验证」徽章（`src/shared/constants/models.ts:171,175`，#1104 真机实测记录）。

### 交互合同

- **开关随发送载荷走**：`searchEnabled` 在用户真实提交路径注入 envelope（`useChatInputEnvelope.ts:144-155`，提交时取现值），编辑/重发旁路同样携带——OFF 就是 OFF，不存在"设了没生效"。
- **凭据专属**：只配了模型 key 不算搜索凭据；无专属凭据时搜索工具不进工具表（`src/host/tools/dispatch/toolDefinitions.ts:107-109` 双闸：逐轮开关 + 专属凭据）。
- **不造假探活**：搜索源探活就是真实检索，不发合成付费探针；401/余额不足分类进 TTL，不再选中（`src/host/services/search/searchSourceRegistry.ts`）。
- **中转不继承官方能力**：中转同名模型不得继承官方能力声明（`deepseek-v4-flash` 走 chat-completions，`0731` 才走 Responses）。

### 异常与恢复

- 固定某个外部源但无凭据：报 `no_credential`，不静默回落到别的源。
- 流式错误响应保留上游原文（#1233），不把供应商错误吞成泛用文案。
- 上下文窗口 / max_tokens / 价格查表带 provider 维度（#1108/#1109），连通性测试用用户原样填的 model（#1111）——配置错了如实报，不做猜测性改写。

### 当前边界

- 逐轮开关控制 Neo 是否调用搜索能力，**不能约束模型供应商自身的训练数据或平台留存政策**（SPEC §5）——设置页文案不得暗示"关了就是隐私"。
- 旧的手工能力配置仍然有效（升级说明），矩阵识别是默认而非强制。

### 验收锚点

- 已实现：`tests/renderer/components/chatInput.envelopeSearchEnabled.test.tsx`（**反向变异门**：主路径 envelope 必须携带提交时刻的 searchEnabled，OFF/ON 正负成对）；`tests/unit/protocol/toolDefinitions.test.ts:108-134`（只配模型 key 不进表；开关 OFF 凭据齐全也不进表）；`tests/unit/services/search/externalSearchService.test.ts`（凭据独立、不发合成探针、余额分类 TTL）；`tests/unit/model/modelCapabilityMatrix.test.ts`（保守默认、中转不继承官方能力）；`tests/unit/model/responsesProvider.test.ts`（端点分流、web_search 由矩阵 gate）。
- 已验证（部分）：`#1092` commit 记录过走产品代码的真机验收（只配智谱 / 只配 MiniMax / auto 选择 / 无凭据报 no_credential 不回落）；`#1103` 的 OFF 态修复是真机复验抓出的漏接。这些是 commit 级记录，docs/ 内无独立验收文档。

## 5. 审批来源表达与 fail-closed

**体验目标**：cowork 的信任底座——需要你确认的操作，没人确认就一律不执行；被拒绝时说清楚**是谁拒的、为什么**。"机器替你批了"必须如实标注为机器批准。

### 入口与状态

- 会话内审批岛：`PermissionCard`（浮于输入框上方，`src/renderer/components/PermissionDialog/PermissionCard.tsx`，y/n/s/a 快捷键直发）。
- 无人值守停车审批收件箱：`AutomationReviewInbox`（含「每次都允许发 target」铸权按钮）。
- 拒绝来源枚举（`src/shared/contract/permission.ts:113-145`）：user / no-approval-ui / timeout / cancelled / fail-closed / scripted；批准来源：user / dev-auto-approve / scripted。给模型和审计的拒绝 reason 唯一来源是 `permissionDenialError()`（`src/host/tools/toolPermissionClassification.ts:74`）——`no-approval-ui` 明说"用户并未看到审批请求"，不再一律 "Permission denied by user"。

### 交互合同

- **无人确认 = 拒绝**：无审批 UI 的 headless 路径一律 `{approved:false, denialSource:'no-approval-ui'}`（`src/cli/permissionPolicy.ts`，#1086 堵掉 `/api/run` 冒名 user 放行的 P0）。
- **便利放行层吃不掉信任边界**：停车判定先于 devModeAutoApprove（#1115）；`$HOME` 写边界 ask 带 `forceConfirm`，任何便利放行层不得跳过（#1118）。
- **机器批准如实自报**：devModeAutoApprove 放行记 `approvalSource:'dev-auto-approve'`，且只在 dev 数据槽判据下有效（`isDevModeAutoApproveEnabled()`，ADR-058；renderer 设置页**没有**这个开关，是有意决策）。
- **评测提权双条件**：`approvalPolicy='e2e-scripted-allow'` 且 `CODE_AGENT_E2E=1` 同时成立才放行（`src/web/routes/devCancellableToolPermissionPolicy.ts`），生产 CLI 路径经断言证明仍 fail-closed。

### 异常与恢复

- ask-denied 落账带完整 trace，reason 写真实来源；分类器自己抛错记 `CLASSIFIER_ERROR_TRACE_RULE/<source>`，trace 不丢（`src/host/tools/toolExecutor.ts:1068-1126`）。
- 审批响应投递链 fail-loud：未知 requestId 报 `PENDING_PERMISSION_NOT_FOUND` 且日志指名，绝不静默 200、绝不回退 legacy handler（`src/web/webPermissionResponseHandler.ts`）。
- 停车审批 drain 记 cancelled、24h 兜底记 timeout——记什么就是什么，不包装。

### 当前边界

- 停车审批收件箱文案是行内中文，未走 i18n（与审批卡核心文案的双语不一致，属欠账）。
- `session/create` 不再静默注册 `$HOME` 为 trusted（#1080）后，历史依赖该行为的工作流需重新授权。

### 验收锚点

- 已实现：`tests/unit/web/devCancellableToolSmoke.test.ts`（双条件提权；生产路径 `no-approval-ui` fail-closed）；`tests/unit/tools/toolExecutor.decisionTrace.test.ts`（**反向变异证明**：分类器抛错变异开关双方向都在测试内跑——变异 → reason 记分类器失败仍拒，还原 → 变回 user；`:186` 无审批 UI 自动拒记 `no-approval-ui` 而非 user）；`tests/unit/permissions/parkingBeforeAutoApprove.test.ts`（停车先于 autoApprove，台账不可用 `denialSource:'fail-closed'`）；`tests/unit/tools/toolExecutor.homeBoundary.test.ts:92-129`（`$HOME` ask 必须 `forceConfirm`）；`tests/unit/web/permissionResponseDelivery.test.ts`（未知 requestId 报错不静默）。
- 未验证：docs/ 内只有决策文档（ADR-058），无修复后的真机验收记录；commit 注释里的真机叙述是**事故复现**（2026-08-13 HOME 写冒名），不是验收。SPEC §6 本行标 fault-injection（指变异测试层），发布级真机验收未做。

## 6. 计划审批与产物跟随

**体验目标**：产物是 cowork 的主轴。动手前，计划摆出来给你改——步骤可编辑，批准才执行；产物生成时，预览主动跟上，不打断你正在做的事。

### 入口与状态

- **计划审批卡**：输入框上方 `PlanApprovalCard`（`src/renderer/components/ChatView.tsx:893-895`；pending 期间输入框保持挂载但隐藏）。步骤可内联编辑、删除、拖拽重排、添加、反馈意见；批准后折叠为存证行 `PlanApprovalEvidence` 回投到工具流。文案 `src/renderer/i18n/planApproval.ts`（`question: '按这个计划开始执行？'`）。
- **产物跟随**：预览面板 `ArtifactFollowToolbar`（生成中态「生成中 · 内容跟随刷新 / 暂停跟随」，完成态 preview/source/edit 三态切换）；`App.tsx` 挂 `useArtifactFollow()`；用户不在预览时产物完成以工作台 tab 关注角标提示（`WorkbenchTabs.tsx:386`），不抢焦点。
- **产物卡降噪**：聊天流内产物文件卡只保留文件名 + 动作（`DeliverableCardList.tsx`），不再渲染验证/质量徽标；右栏状态徽章改人话「已就绪 / 未检查 / 有问题」（`src/renderer/i18n/zh.ts:92-94`），「已验证/未验证」是内部口径不上卡面。

### 交互合同

- **未批准不执行**：run 停在审批边界（`planApprovalRunBoundary.ts` 的 `shouldEndRunForPlanApproval`），批准前的任何执行不得继续。
- **编辑即重签**：内联编辑保存前禁批准；批准把编辑后步骤原子替换进 task ledger 并开新 turn；已决议的审批防重放。
- **跟随有礼貌**：生成中自动跟随只发生在用户空闲时；用户最近在工作台交互过则降级为后台打开 + attention 角标（`src/renderer/hooks/useArtifactFollow.ts`）。完成时产物卡锚定到真实完成播报所在轮，只移动不复制（`useTurnProjection.ts:163-166`）。

### 异常与恢复

- 提交失败如实提示「计划决定未生效，请重试。」（`planApproval.submitFailed`），不静默吞决议。
- 取消不替换任务；ledger 替换是原子的（`replaceTasksAtomically`），不留半新半旧。

### 当前边界

- 产物跟随只认一期文件类型（`tests/renderer/utils/artifactFollow.test.ts` 明写 phase-one），非全类型产物。
- CLI autoApprove 语义保持不变（审批边界不伤 CLI 自动批准路径）。

### 验收锚点

- 已实现：`tests/unit/agent/planApprovalRunBoundary.test.ts`（**fail-closed 核心**：未批准时 desktop run 停在执行前；不误伤无关确认）；`tests/unit/services/planApprovalService.test.ts`（原子替换、防重放拒绝）；`tests/renderer/components/planApprovalCard.test.tsx`（编辑保存前禁批准、编辑后顺序只提交一次）；`tests/renderer/hooks/useArtifactFollow.test.tsx`（空闲自动开、近期交互降级后台 + attention）；`tests/renderer/components/deliverableCardList.test.tsx:144-183`（**反向变异证明**：verified/unverified/failed 三态逐一断言卡面不出现徽章——"只断言 verified 会让另两态从别的分支漏出来"）；`tests/renderer/components/previewPanel.htmlLocality.test.tsx:194-195`（右栏人话文案三态）。
- 未验证：SPEC §6 计划审批与产物跟随两行均标 `hermetic-protocol`；无 e2e 用例，无真机验收记录。

## 7. 文案与视觉细节

**体验目标**：细节不抢戏但要经看——用户凝视这个工具以小时计（设计系统 §2 舷窗原则）。本版一批"小但天天见"的阅读质量修复。

### 合同与锚点

- **mermaid 图表跟随明暗**（#1240）：`useMermaidTheme()` 盯 `data-theme`，四档应用主题映射两档 mermaid 主题，主题切换必须重初始化（`src/renderer/components/features/chat/MessageBubble/mermaidTheme.ts`、`mermaidLoader.ts`）。浅色下节点不再是纯黑块。锚点：`tests/unit/renderer/mermaidLoader.test.ts`（浅色档深文字、dark→light→dark 必须 initialize 3 次；反向变异记录在测试注释）。**注意**：mermaid 字面色靠 `ds-allow:start/end` 区块豁免过 hex 门，设计系统守卫并不正向校验它。
