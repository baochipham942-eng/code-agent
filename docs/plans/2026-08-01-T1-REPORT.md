
## 2. 施工项逐条

### ① Run header

数据源全部是既有 run/turn 状态，零新增轮询：

- `RunUiState` 加两个字段 `startedAt` / `endedAt`，在 `buildRunUiState`（`src/renderer/utils/runWorkbenchProjection.ts`）里直接取自 `TraceTurn.startTime/endTime` —— 就是 TaskMonitor/TaskDashboard 用的同一份投影。
- 视图模型是纯函数 `buildOverviewRunHeaderModel`（`src/renderer/utils/overviewRunHeader.ts`），组件 `TaskPanel/OverviewRunHeader.tsx` 只负责渲染与秒表。
- **「有没有 run」只认 `identity.turnId`，不认 `run.status`**：`statusFromInput` 对空会话默认返回 `'completed'`，拿状态判存在会给从没跑过的会话摆一条「已完成」表头（工单 §4「不摆空 Run header」）。
- 秒表 `setInterval` 只在 `isLiveRunStatus(status)` 为真时装；跑完停表，用时冻结在 `endedAt`。起点未知时显示 null，不假造 `0:00`。
- 中断按钮走 `runControlStore.actions.interrupt`，即 `useAgent().cancel`（`agent:cancel` IPC 带重投递与 honest settle）。**本批没有重新实现任何一条取消链路。**

顺带收敛：`LIVE_RUN_STATUSES` 此前在 `useTaskActivity.ts` 与 `RunWorkbenchCards.tsx` 各存一份完全相同的副本，本批要用第三次，收敛成 `overviewRunHeader.isLiveRunStatus` 单一真源。

### ② steering queue 投影

**host 侧 handler 齐全，无缺口。** 核过的既有 IPC（`src/host/ipc/queuedInput.ipc.ts`，注册于 `src/host/ipc/index.ts:209`）：

| 动作 | Schema | renderer 既有实现 |
|------|--------|-------------------|
| 列出 | `QueuedInputSchemas.LIST` | `useAgent.hydrateQueuedRuntimeInputs` |
| 删除 | `QueuedInputSchemas.RETRACT` | `useAgent.cancelQueuedRuntimeInput` |
| 立即发送 | `MARK_SENDING` + `REPORT_SEND_OUTCOME` | `useAgent.sendQueuedRuntimeInput`（跑中走 `steerQueuedRuntimeInput` 立即转向） |

真正的障碍不是 handler 缺失，而是**位置**：队列状态和这三个回调都在 `useAgent` 里，而 `useAgent()` 全应用只在 `ChatView` 挂一次；右栏 Overview 由 `App.tsx` 渲染，是另一棵子树，拿不到。

解法是一个只做投影的小 store `src/renderer/stores/runControlStore.ts`：

- **`useAgent` 是唯一写入方**。队列在 `visibleQueuedRuntimeInputs`（就是 ChatInput 排队卡拿的同一份，按 `currentSessionId` 过滤）上推，两处永远不会对「还有几条在排队」各说各话。
- 动作是**把既有回调原样交出去**（`interrupt: cancel` / `retractQueued: cancelQueuedRuntimeInput` / `sendQueuedNow: sendQueuedRuntimeInput`）。Overview 侧不发任何 IPC、不复制任何一段 markSending/reportSendOutcome 生命周期逻辑。
- `useAgent` 卸载时 `publishActions(null)` + 清空队列——聊天运行时不在时留着动作，等于给 Overview 一批点了没反应的按钮。`OverviewSteeringQueue` 在 `actions === null` 时不渲染按钮。
- 发送失败（`sendFailed`）的条目只留删除，不摆宿主已不接受重发的发送按钮。

另修一处会让队列不可达的边：`WorkbenchOverview` 原来只按 `hasTaskActivity || hasArtifacts` 决定是否进空态。中断后 run 活动信号会落回 false 而队列还在，队列就被锁死在空态后面。现在把 `hasQueuedInputs` 一起算进去。

**host steering 语义零改动**——本批没有碰 `agentOrchestrator.ts` / `steerQueueFence.ts` / `QueuedInputRepository`，diff 里没有任何 `src/host/` 文件。

### ③ 诊断下沉

原「上下文」卡（AgentTree + 能力路由/Skill/MCP/Memory/文件行）改标题为「诊断详情」，`defaultExpanded={false}`，移到块序最后。`storageKey` 从 `overview-context` 换成 `overview-diagnostics`，让新的折叠默认对存量用户也生效（老键的展开偏好不再被读到）。**内容一条未删**：`AgentTreeView` 与 `ContextRows` 原样保留，只是不再抢主视线（调研 §4.5）。

顺带一条现状核实：`TaskMonitor.tsx`（33.9K）**在 app 里没有任何挂载点**，全仓库只有两个测试文件引用它。工单描述的「TaskPanel = AgentTree + TaskMonitor」在当前代码里已不成立，Overview 主视线里被诊断占掉的实际是 AgentTree + 上下文行。已按实际形态施工，未动 TaskMonitor 文件本身。

### ④ 空态

无 run 时 Run header 整块不渲染，队列为空时队列卡整块不渲染。原有的产物/欢迎叙事空态未改。

## 4. 证据档位

- **hermetic-protocol**：队列投影链路（renderer store → useAgent 回调 → host QueuedInput IPC）用 mock 过的 `typedInvokeDomain` 真跑，断言落到具体 schema 与 payload。
- **static-contract**：Run header 三态、用时计算、块序、诊断折叠。
- **未做 real-runtime**：本批全是 renderer 侧投影与排版，host 协议零字节改动；Run header 的时间来源 `TraceTurn.startTime/endTime` 是既有投影字段，不新增任何跨进程契约。真机观感（Run header 在长任务里是否够醒目、诊断折叠后 power user 找不找得到）属于审美关范畴，留给产品负责人验收。
