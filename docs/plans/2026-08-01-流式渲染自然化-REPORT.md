### 语义对应工单四条

1. **积压直落**：`BACKLOG_DIRECT_LAND_CHARS = 200`。待播积压 > 200 字符时，超出部分当帧落地，
   只留最后 200 字符参与播放——任何情况下从左到右的扫描不超过约一行。
2. **尾部生长**：粒度从字符改为「词/短段」（`findSmoothStreamingSegmentEnd`：拉丁按词、
   中文按句读或 `CJK_SEGMENT_MAX_CHARS = 10` 字上限），节奏 `TAIL_SEGMENT_INTERVAL_MS = 120`，
   跨帧攒额度，一个间隔落一段。最新段落由消费层包进 `streaming-tail-segment` span
   （key 随段首下标变化），mount 时跑 120ms 透明度淡入（纯 CSS keyframes，无动画库）。
   直落的大块不包 span、不淡入——立即可读。
3. **prefers-reduced-motion**：hook 内 `matchMedia('(prefers-reduced-motion: reduce)')` 命中即
   全量直落、`isAnimating=false`、不调度 rAF；CSS 侧 `.streaming-tail-segment` 动画同步关闭。
4. **契约保持**：`isAnimating` 语义不变（动画中=true）。流结束（flush）剩余尾巴一次落定，
   `isAnimating` 更快变 false——按钮行追平（#871）属正向受益。
   `turnCard.replyActions.typewriterCatchUp` 两例**原样未动、全绿**。

常量全部集中在 `SMOOTH_STREAMING_TEXT_DEFAULTS`；z-index 未触碰；旧的 CPS/flush 魔法数
（`MIN_CPS`/`DEFAULT_CPS`/`MAX_CPS`/`FLUSH_MAX_SECONDS`/`flushRemainingMs`）随语义重写移除。

## 一、历史会话加载骨架屏（commit `ecbe012a5`）

### 三态判定与渲染

| 态 | 判定 | 渲染 |
|----|------|------|
| 加载中 | `sessionStore.isHydratingSession = true`（switchSession 置位，成功/空/异常三出口落回） | `SessionSwitchSkeleton`：3 条左右气泡轮廓 + shimmer 扫光，输入框正常可用 |

- **信号**：没有复用 `isLoading`（它与 `loadSessions` 列表刷新共用，语义不纯），按工单允许
  在 switchSession 里补了独立的 `isHydratingSession` 标记；竞态沿用 `_switchCounter`
  （过期切换的响应直接丢弃，不动新版本持有的标记）。
- **三态裁决**：ChatView 空分支抽成 `EmptySessionArea`（`SessionSwitchSkeleton.tsx`），
  settled → welcome；hydrating → 骨架屏；冷启动未定会话 → 原空白占位。

  （`visible` 门控，fake-timers 单测锁定）；快速切换全程无骨架，消失即换真内容无过渡。

  （静态占位）；CSS 侧同步把 `.animate-shimmer` 并入既有 reduced-motion 豁免段。
- **设计系统**：复用闲置的 `.animate-shimmer`（`global.css:539`）+ tailwind `bg-zinc-800/40`

## 二、侧栏归档两修

### 1. 归档图标垂直没对齐（commit `70a509d95`）

对照 `SidebarProjectGroup` 同款 hover 簇（`SidebarProjectGroup.tsx:250`）修三处
（`SidebarSessionItem.tsx` 归档动作簇）：

- 补 `z-10`——原簇无 z-index，会被行内容压住/错位（项目簇有）。
- `right-2` → `right-1.5`——与行内容右缘（`pr-1.5`）同轨，图标落在被它顶替的
  行尾状态点同一竖轨。
- 删死 class `!p-1`——Tailwind v4 的 important 是后缀写法（`p-1!`），v3 前缀写法
  不生成任何 CSS（`size="sm"` 本就 `p-1`，全仓仅此一处）。

### 2. 归档连点无响应（commit `24b712d12`）

- **定因**：不存在全局锁/disabled 吞点击（全仓 grep 无 archiving/pending 守卫）。根因是
  host 每次归档在响应前广播 `SESSION_LIST_UPDATED`，而 `invokeDomain` 的 in-flight
  dedupe（`ipcService.ts:169-184`）把第二次广播触发的 `loadSessions` 并进第一次的在途
  `list` 请求——它拿到的是归档前的陈旧快照，签名比对不一致后 `set({sessions})` 把刚归档的
  行以未归档态写回，之后不会再有广播，行就一直挂着。host/IPC 层（better-sqlite3 同步写 +
  本地同步读）可排除，根因在展示/数据层。
- **修复（展示层，未越界 host）**：
  - `archiveSession` 改**乐观移除/置标**（active 过滤行先消失），IPC 失败**回滚**旧列表 +
    置 error；归档当前会话的 switchSession 仍在 IPC 落定后走（不进乐观路径）。
  - sessionStore 加 `_sessionsLocalVersion` 本地变更版本号（archive/unarchive/delete 变更时
    +1），`loadSessions` 落地前比对：在途期间发生过本地变更就**丢弃陈旧快照重取**，
    不再把旧列表写回。
