## P1 · 画面交互透传

### 根因

二期把浏览器 tab 做成了实时画面观察窗 + 地址栏/工具条，但画面本身是只读 `<img object-contain>`：

- 用户点击/滚轮/键盘落在 renderer DOM，**没有**映射到托管浏览器视口坐标；
- host 侧虽有 agent 用的 `clickAtPosition` / `typeAtFocus` 等，**没有**面向用户画面的白名单 IPC；
- 地址栏已具备「agent 忙 → 抢占确认」与外会话禁用，画面交互未复用同一语义。

产品负责人判据「没法在百度框里打字→搜索→后退」因此卡死在「看得见但不能上手」。

### 改动

**纯函数 / 门控**

- `src/shared/utils/browserFrameCoordinateMap.ts`：`object-contain` letterbox/pillarbox 偏移 + 缩放 → 视口 CSS 像素；黑边点击返回 null。
- `src/shared/utils/userBrowserInputPayload.ts`：白名单 `click|wheel|key|insertText`；越界坐标/非法 key/控制字符拒绝；**禁止** `cdpMethod` / `method` / `params` / `Input.*` 任意 CDP 直通。
- `src/renderer/utils/browserStageInteractionGate.ts`：外会话禁、批注互斥、agent 忙首次确认、已确认后透传。

**Host 通道**

- `UserBrowserLinkService.dispatchUserInput`：与 history 同链路（`conversationId` + `workspace` + user-browser-link run）；与 agent 共享物理窗（既有 ensureBinding 共享语义）。
- `workspace.ipc`：`dispatchUserBrowserInput` action。
- `userBrowserInputDispatch.ts`：仅 Playwright mouse/keyboard 白名单实现（click/wheel/press/insertText），无 CDP 方法透传。

**Renderer**

- `useBrowserStageUserInput`：坐标映射 + 门控 + IME（`compositionend` → insertText，组合中不逐键透传）+ Escape 失焦。
- `BrowserAgentWindow`：实时画面可聚焦（tabIndex + 可见 focus ring）；批注模式仍独占点击；抢占确认复用既有 `ConfirmDialog`（操作文案 `interruptConfirmOperate`）。

**导航联动**

- 透传点击引发的页面跳转走既有 page load / session broadcast → 二期 `canGoBack` / 地址栏 URL 回写 / 页签标题自然更新，无需另接线。

## R3 真机证据（导航联动返工 · 小格）

**环境**：`WEB_PORT=8281` + `CODE_AGENT_DATA_DIR=$HOME/.code-agent-web975` + `CODE_AGENT_DISABLE_RENDERER_HOT_UPDATE=1` + 本 worktree `npm run build`

**证据档位**：real-runtime（web 真机 DOM）+ hermetic-protocol（补回归单测）+ static-contract（typecheck）

### 根因（证实）

R2 透传与历史已通；监工复验「有机跳转后地址栏/标题/后退」FAIL，根因有三层叠在一起：

1. **UI chrome 优先 surface origin/title，且同源闸过严**
   `BrowserAgentWindow` 在存在 surface 会话时：标题永远取 `browserSurfaceTitle`；地址栏只有 `managedUrl.startsWith(browserSurfaceOrigin)` 才用 managed 完整 URL，否则回落 surface origin。
   用户透传引发的有机跳转（表单/重定向）**不经** `adapter.execute`，surface `activeTarget` 不更新 → 跨域（`www.baidu.com` → `wappass.baidu.com`）时地址栏卡死旧 origin、页签标题卡死旧标题。

2. **`getManagedBrowserSession` 读默认 BrowserService 单例**
   user-browser-link / agent surface 用 `ManagedBrowserProviderAdapter` 的独立 `BrowserService`（`surface-${hash(...)}`）。
   page_load 广播的是绑定实例的正确 URL/canGoBack，但 5s 轮询 `loadManagedBrowserSession` 会用空单例覆盖 → 后退可用态被刷灰。

3. **有机导航事件 → surface 观测未接通**
   `page.on('load')` 虽会 `refreshTabMetadata` + `emitSessionChanged('page_load')`，但 surface binding 的 activeTarget 只在显式 execute 后 `captureObservation` 更新；用户透传路径没有这步。

### 修复

| 层 | 改动 |
|----|------|
| `BrowserService` | load 失败也尽量广播；主 frame `framenavigated` 提前回写；`onSessionChanged` 订阅 |
| `ManagedBrowserProviderAdapter` | `getPreferredUiSessionState()` 优先 user-browser-link 绑定实例；绑定后挂有机导航钩子，page_load/navigate/history/reload → `captureObservation` 对齐 activeTarget |
| `desktop.ipc` `getManagedBrowserSession` | 优先 `getPreferredUiSessionState()`，再回落默认单例 |
| `BrowserAgentWindow` | managed tab URL/title 为实时真源；surface origin/title 仅 managed 空时兜底（同窗跨域有机跳转可回写） |
| `WorkbenchTabs` | 页签标题/tooltip 优先 managed tab（与地址栏同源） |
