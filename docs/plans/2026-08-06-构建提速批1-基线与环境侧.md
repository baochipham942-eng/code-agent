## 背景（读懂再动手）

Neo 的 dev 测试包构建成本几乎全在 Rust 侧，已实测：

- `npm run build` 四步合计只有 **10.5 秒**（worker 0.23 / web 2.51 / cli 1.73 / renderer 6.03）
- 主树**没有** `src-tauri/target`，每次打包冷编 **555 个 crate**
- `[profile.release]` 开着 `lto = true` + `codegen-units = 1`
- 近 60 天 1715 个提交里只有 34 个（2%）碰过 Rust

推论：98% 的重打包本该是 cargo no-op，现在次次冷编译，因为编译产物每个 worktree 各一份、主树一份没有。

**本批只做「测量 + 机器环境侧」，不改仓库任何代码。** 代码改动在批 2/批 3，本工单里一律不许动。

## 前置：准备一个干净 worktree

主树 `~/Downloads/ai/code-agent` 是脏的且可能落后，**不要在主树里构建**。

```bash
cd ~/Downloads/ai/code-agent
git fetch origin main
git worktree add /tmp/neo-buildbench -b bench/build-cost origin/main
```

然后把 gitignored 的构建输入补齐（这些东西不在 git 里，新 worktree 一定缺）：

```bash
SRC=~/Downloads/ai/code-agent
WT=/tmp/neo-buildbench

# 只读输入 → 软链
ln -sfn "$SRC/node_modules" "$WT/node_modules"
for f in rtk uv poppler system-audio-capture vision-ocr vision-tagger voice-aec-io; do
  ln -sfn "$SRC/scripts/$f" "$WT/scripts/$f"
done

# 会被写的 → 必须拷贝，软链会写穿透污染主树
mkdir -p "$WT/dist"
cp -R "$SRC/dist/native" "$WT/dist/native"
cp -R "$SRC/dist/bundled-node" "$WT/dist/bundled-node"
```

cua helper **不用管**：`stage-cua-driver-resource.sh` 会自动从机器级缓存
`~/Library/Caches/agent-neo/cua/` 恢复（2026-08-06 刚上线的机制）。如果它报错说找不到，
**停下报告**，不要自己去跑 `fetch-cua-driver.sh`（那要下载 + Developer ID 重签）。

构建都需要代理：`HTTPS_PROXY=http://127.0.0.1:7897`。

## 要跑的三次构建

每次构建前都 `cd /tmp/neo-buildbench`，并且**先把 cargo 产物清干净**保证是冷构建：
`rm -rf src-tauri/target`（第一次本来就没有，可跳过）。

### B1 — 现状基线（LTO on，无 sccache）

```bash
cd /tmp/neo-buildbench
time (HTTPS_PROXY=http://127.0.0.1:7897 NEO_SLOT=2 npm run tauri:build:dev)
```

B1 有**双重目的**，两个都要在报告里回答：

1. 拿到「现状冷构建」的墙钟时间；
2. **验证槽 2 真机可用**（这是上一轮遗留未验的项）。装完后核对：
   - `/Applications/Agent Neo Dev 2.app` 存在
   - `codesign -dv "/Applications/Agent Neo Dev 2.app" 2>&1 | grep Identifier` → `com.linchen.code-agent.dev2`
   - 启动它，`curl -s http://127.0.0.1:8182/api/health` 返回 200
   - `ls -d ~/.code-agent-dev2` 存在，且 `~/.code-agent-dev`（槽 1）**没有被新建/改动**
   - 槽 1 的 `/Applications/Agent Neo Dev.app` 仍在、没被覆盖（比对安装前后的 `ls -l` 时间戳）
   - 验完把 `Agent Neo Dev 2.app` 退出（别让它一直占着 8182）

### B2 — 关 LTO（填 sccache 缓存）

先装 sccache 并全局启用：

```bash
brew install sccache
cp ~/.cargo/config.toml ~/.cargo/config.toml.bak-0806 2>/dev/null || true
# 在 ~/.cargo/config.toml 里加（若已有 [build] 段就并进去，别覆盖既有内容）：
#   [build]
#   rustc-wrapper = "sccache"
sccache --zero-stats
```

然后：

```bash
cd /tmp/neo-buildbench
rm -rf src-tauri/target
time (HTTPS_PROXY=http://127.0.0.1:7897 \
      CARGO_PROFILE_RELEASE_LTO=false CARGO_PROFILE_RELEASE_CODEGEN_UNITS=16 \
      NEO_SLOT=2 npm run tauri:build:dev)
sccache --show-stats
```

### B3 — sccache 热命中（这才是「以后每个新 worktree 的真实成本」）

```bash
cd /tmp/neo-buildbench
rm -rf src-tauri/target
sccache --zero-stats
time (HTTPS_PROXY=http://127.0.0.1:7897 \
      CARGO_PROFILE_RELEASE_LTO=false CARGO_PROFILE_RELEASE_CODEGEN_UNITS=16 \
      NEO_SLOT=2 npm run tauri:build:dev)
sccache --show-stats
```

B3 的 `--show-stats` 要能看到高比例的 cache hits。**如果命中率很低，不要粉饰**——
如实报告命中率和你观察到的原因（例如 sccache 对某类 crate 不缓存）。

## 报告

写到 `~/Downloads/ai/code-agent/docs/plans/2026-08-06-构建提速批1-实测报告.md`，必须包含：

1. **三次构建的墙钟时间表**（B1 / B2 / B3），以及 B1→B3 的绝对节省和百分比。
   `time` 的原始输出（real/user/sys）逐条贴上。
2. **拆分**：能拆出 npm build 段和 cargo 段各自耗时就拆（构建输出里有阶段标记）；拆不出就写明拆不出，别编。
3. **B2/B3 的 `sccache --show-stats` 原始输出**（compile requests / cache hits / cache misses）。
4. **槽 2 真机验证结论**：上面那 6 条逐条写实际观察到的值，不是"符合预期"四个字。
5. **产物体积对照**：`du -sh "/Applications/Agent Neo Dev 2.app"` 在 B1（LTO on）与 B3（LTO off）下各是多少
   —— 关 LTO 会让二进制变大，得知道大多少。
6. **回退方法**：怎么撤掉 sccache（恢复 `~/.cargo/config.toml.bak-0806`、`brew uninstall sccache`）。
7. **异常与偏差**：任何一步和工单写的不一样，如实写；包括你觉得工单写错的地方。
