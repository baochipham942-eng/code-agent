## 2. 耗时拆分（npm 段 vs cargo 段）

拆分依据：构建日志中 cargo 自报 `Finished \`release\` profile ... in Xm XXs`，npm 各步有自带毫秒标记。三次构建的非 cargo 部分高度稳定：

| 阶段 | B1 | B2 | B3 |
|---|---|---|---|
| build:web（esbuild Web Server） | 1412ms | 1211ms | 1247ms |
| build:cli（esbuild CLI） | 1096ms | 1428ms | 892ms |
| build:renderer（vite `✓ built in`） | 3.04s | 2.76s | 2.61s |
| **cargo 段（含最终链接与 bundle 前的编译）** | **3m 56s** | **2m 47s** | **1m 13s** |
| 总 real 减去 cargo 段（≈npm/原生模块/扫描/打包/安装等固定开销） | ≈84s | ≈75s | ≈74s |

结论：固定开销约 74–84 秒（rebuild-native、npm build 四步、webserver boot 验证、security-scan、bundle、安装到 /Applications），三次构建间基本一致；变量全在 cargo 段。sccache 热命中把 cargo 段从 3m56s 压到 1m13s，剩下的 73s 主要是：75 个不可缓存的 proc-macro crate 编译 + 最终 `code-agent-tauri` 主 crate 的 codegen 与链接（链接不被 sccache 缓存）。

## 6. 机器级改动与回退方法

本批唯一机器级改动：

1. `brew install sccache`（0.17.0）
2. 新建 `~/.cargo/config.toml`，内容：
   ```toml
   [build]
   rustc-wrapper = "sccache"
   ```
   **注意：这对本机所有 Rust 项目生效。**

**偏差说明**：工单要求改动前备份成 `~/.cargo/config.toml.bak-0806`，但本机**原本不存在** `~/.cargo/config.toml`，执行了 `cp ... || true`，无备份文件产生。因此回退 = 删除该文件即可。

回退命令（需要时执行，本次按工单要求保留不撤）：

```bash
rm ~/.cargo/config.toml            # 恢复原状（原本无此文件）；若将来有了自有配置，改为从中删除 rustc-wrapper 行
brew uninstall sccache
rm -rf ~/Library/Caches/Mozilla.sccache   # 可选，清缓存（当前 283 MiB）
```

## 7. 异常与偏差（如实记录）

1. **`~/.cargo/config.toml` 原本不存在**，无 `.bak-0806` 备份产生，回退方式相应变为删文件（见第 6 节）。
2. **四个 swift helper 二进制的软链被构建脚本"安全顶掉"**：`tauri-prebuild-cleanup` 阶段重编了 `system-audio-capture / voice-aec-io / vision-ocr / vision-tagger`，写法是先编再替换，导致 worktree 里这 4 个软链被替换为真实文件（`scripts/` 下的链接断开）。写穿透**没有发生**——主树 `~/Downloads/ai/code-agent/scripts/` 下对应二进制 mtime 保持 Apr 9 / Aug 2 / May 19 不变，逐一核对过。结论：工单"只读输入软链"的假设对 rtk/uv/poppler 成立，对这 4 个会在构建中被重编的 helper 不成立，但也无污染主树，无需处理；后续工单若要严格隔离，可改为拷贝。
3. **`~/.code-agent-dev`（槽 1）mtime 在构建窗口内变化**：排查确认是槽 1 应用自身在跑（PID 56039/56053，22:09:40 启动，`/Applications/Agent Neo Dev.app/Contents/MacOS/code-agent-tauri`），变动的是它自己的运行时文件。不是本构建触碰。
4. **sccache 报 `Compilation failures 7`**（B2、B3 两轮相同）：构建均 exit 0，产物完整可签名可安装，判断为 sccache 对个别 crate 的缓存预处理失败后回退直编的计数。不影响结论，列出备查。
5. **构建结束提示语有误导**：安装脚本打印 `测试包独立运行（数据目录 ~/.code-agent-dev）`，但槽 2 实际数据目录是 `~/.code-agent-dev2`（已实证）。是脚本提示文案没按槽位替换，行为本身正确。建议批 2/3 顺手修。
6. **cargo 段 3 次时间取自 cargo 自报 `Finished ... in Xm XXs`**，该值不含 bundle/安装；总 real 与 cargo 段的差值（74–84s）作为"固定开销"是推算值，不是独立计时，已在第 2 节标明口径。
7. macOS 下 `/tmp` 实为 `/private/tmp`，日志与 cargo 输出里路径显示为 `/private/tmp/neo-buildbench`，与工单路径是同一目录。
