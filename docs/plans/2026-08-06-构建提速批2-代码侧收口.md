## 改动 1：装完自动清本槽的 renderer 热更新缓存

**问题**：webServer 优先 serve `<数据目录>/renderer-cache/active`，所以改了 renderer 重新打包后
**不清缓存看到的还是旧版**。这个坑在 `CLAUDE.md` 里警告了两处、记忆里也记着，但补救方式一直是
「记得手动 `rm -rf`」——靠记性的护栏迟早漏，而漏了的表现是**白跑一轮验收**（2026-06-07 已实测踩过）。

**做什么**：`scripts/tauri-install-dev.sh` 在安装成功后，删掉**本槽**的
`$HOME/<dataDirName>/renderer-cache/active`。

- 槽位数据目录名**已经在** `src-tauri/.dev-slot.json` 的 `dataDirName` 字段里，用现成的
  `read_slot_field dataDirName` 读，**不要在 shell 里另算一遍**。
- 只删 `renderer-cache/active`，**不要**删整个 `renderer-cache/`，更不要碰数据目录里任何其他东西。
- 目录不存在时静默跳过（`rm -rf` 本身就是幂等的），但要 `echo` 一行说明做了这个动作，
  别让用户以为没清。

## 改动 2：删掉 DMG 死代码

`src-tauri/tauri.conf.json` 的 `bundle.targets` 已经是 `["app"]`，压根不产 DMG，
但 `scripts/tauri-install-dev.sh` 里还留着：

```bash
for vol in /Volumes/"$APP_NAME"*; do
  [ -d "$vol" ] && hdiutil detach "$vol" 2>/dev/null || true
done
```

它不只是死代码，还是**前缀 glob**——槽 1 的 `Agent Neo Dev*` 会匹配到槽 2 的卷，
和刚修掉的 `pkill` 前缀互相命中是同一个病。**整段删掉。**

（注意：生产安装脚本 `scripts/tauri-install.sh` 里的同类逻辑**不要动**，本批只管 dev。）

## 改动 3：修安装脚本结尾的误导提示语

`scripts/tauri-install-dev.sh` 结尾那句提示把数据目录写死成 `~/.code-agent-dev`，
但槽 2 实际是 `~/.code-agent-dev2`。改成用 `read_slot_field dataDirName` 的真实值。
批 1 实测发现（报告第 7 节）。

## 改动 4：dev 包默认关 LTO，留逃生口

`[profile.release]` 的 `lto = true` + `codegen-units = 1` 是给**发版包**的优化，
对每天验行为的测试包是纯浪费（实测 cargo 段省 68%，体积只涨 0.5%）。

**做什么**：在 `package.json` 的 `tauri:package:dev` 里默认带上 env 覆盖：

```
CARGO_PROFILE_RELEASE_LTO=${NEO_DEV_FULL_LTO:+true}...
```

具体写法你定，但必须满足：

- **默认**（不设任何 env）→ `CARGO_PROFILE_RELEASE_LTO=false` + `CARGO_PROFILE_RELEASE_CODEGEN_UNITS=16`
- **`NEO_DEV_FULL_LTO=1`** → 恢复成和发版包一样的 LTO 全开（不设这两个变量，让 Cargo.toml 生效）
- **绝不改 `src-tauri/Cargo.toml`**——那会影响 CI 发版
- 只作用于 `tauri:package:dev`，`tauri:package` / `tauri:release:bundle` 一律不受影响

**为什么留逃生口**：测试包存在的意义是「除身份外一切与生产同构」。98% 的场景是验行为，
关 LTO 无所谓；但要验启动性能/时序时（Neo 有过开机 SIGBUS 事故），得能一键切回同构构建。

**同时**：`❌ 不要`改用 `cargo tauri build --debug` 来省时间——它翻转 `cfg!(debug_assertions)`，
`web_server_node_env()` 会返回 `development`，测试包运行环境就和真包不一样了。
