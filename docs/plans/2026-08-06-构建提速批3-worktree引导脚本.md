## 背景与要解决的问题

新开一个 worktree 之后，它**不能直接打 dev 包**，因为一堆构建输入是 gitignored 的：

| 缺什么 | 体积 | 怎么来的 |
|---|---|---|
| `node_modules` | 783 个包 | 主树已有 |
| `scripts/rtk` | 7.2M | `fetch-rtk.sh` 网络下载 |
| `scripts/uv` | 45M | `fetch-uv.sh` 网络下载 |
| `scripts/poppler` | — | `fetch-poppler.sh`，**要 homebrew 现编** |
| `scripts/system-audio-capture`、`voice-aec-io`、`vision-ocr`、`vision-tagger` | 各 ~100K | swift 现编 |
| `dist/native` | 1.9M | `rebuild-native:system` |
| `dist/bundled-node` | 115M | `prepare-bundled-node.mjs` |
| cua helper `.app` | — | **已解决**，`stage-cua-driver-resource.sh` 自动从 `~/Library/Caches/agent-neo/cua/` 恢复 |

现在这些全靠人手工补，而且**漏了是静默的**：漏 `node_modules` 时 `npx tsx` 照跑（它自己去下载），
但 `vitest` / `tsc` 会给你一片**假红**——编排会话 2026-08-06 就先踩了这个。

## 关键约束（批 1 实测得出，别搞错）

**软链 vs 拷贝不是随便选的：**

- **可以软链**（构建期只读）：`node_modules`、`scripts/rtk`、`scripts/uv`、`scripts/poppler`
- **必须拷贝**（构建期会被写）：
  - `dist/native`、`dist/bundled-node` —— 软链会**写穿透污染主树**（记忆里的老坑）
  - `scripts/system-audio-capture`、`scripts/voice-aec-io`、`scripts/vision-ocr`、`scripts/vision-tagger`
    —— 批 1 实测：`tauri-prebuild-cleanup` 阶段会**重编这 4 个 swift helper**，
    写法是先编再替换，于是 worktree 里的软链被顶成真实文件（那次没污染主树，但这是运气不是设计）

## 硬规则

1. **新增文件只有一个**：`scripts/worktree-bootstrap.sh`。外加它的测试与文档更新。
   不许顺手改别的脚本、不许重构。
2. **仓库结构棘轮**：新增根层脚本会让 `scripts/ci/check-repository-structure.mjs` 的
   `directScriptFiles` 超限。按现有注释风格**带日期和理由**把它 +1，并在 commit message 里说明。
   （该脚本是 `package.json` 的稳定入口，符合 `scripts/README.md` 的根层保留条件。）
3. **类型门第一硬规则**：`npm run typecheck` 必过 + `node scripts/tsc-tests-ratchet.mjs` 不超基线。
4. **脚本必须 fail-closed**：任何一步失败就非零退出并**指名道姓**说缺什么、去哪补，
   不许静默跳过。（参考 `stage-cua-driver-resource.sh` 的报错风格。）
5. **绝不写主树**。脚本只往目标 worktree 里写；从主树只读取。
   这一条要有测试或自检来保证，不能只靠注释。
6. `ship pr` 开完 PR **停住，禁止 merge**。
7. 失败停下如实报告，不绕过。同一步骤连挂 2 次就停。不派子代理、不中途提问。

## 脚本要求

`scripts/worktree-bootstrap.sh`，用法：

```bash
bash scripts/worktree-bootstrap.sh <目标worktree路径> [--source <主树路径>]
```

- `--source` 缺省 = 本脚本所在仓库的根（即从哪棵树复制）
- **幂等**：重复跑不报错、不重复拷贝已经就位且一致的东西
- 目标路径不是一个 git worktree 时**拒绝执行**（别让人误把主树当目标）
- 目标 == 源时**拒绝执行**（自我引导没有意义，且可能自毁）
- 逐项输出做了什么（`link` / `copy` / `skip`），最后打一行汇总
- 结尾跑一次 `stage-cua-driver-resource.sh` 补 cua helper；它失败**不致命**
  （dev 包才需要，纯跑测试的 worktree 不需要），但要**明确 warn**，不许静默吞

**源缺件的处理**：如果主树自己也缺（比如 `dist/bundled-node` 不存在），
**不要**自动去跑 `fetch-*.sh` / `prepare-bundled-node.mjs`（那些要网络、要 homebrew、要几分钟）。
应当明确报出「主树缺 X，请先在主树跑 <命令>」然后非零退出。理由：无人值守时静默启动
一个几分钟的下载/编译，比直接报错更难排查。

## 测试

- **真跑**：用 `mkdtemp` 造一个假的「源」和「目标」目录结构（塞几个假文件即可，不要真的

  - 幂等：连跑两次结果一致、退出码 0
