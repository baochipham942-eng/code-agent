## 1. 三洞改动摘要

### 洞① Windows 更新路径不经过 cleanup_server

`src-tauri/src/main.rs` 新增 `#[tauri::command] shutdown_web_server_for_update`，
内部直接调 `cleanup_server(&app)`（`AppState::cleanup()` 是 `take()` 语义，天然幂等）。
`generate_handler!` 注册 + `permissions/app-commands.toml` 的 `allow-renderer-commands`
白名单同步加入。

渲染器 `src/renderer/utils/tauriUpdater.ts` 的 `tauriInstallUpdate` 把原来一次性的
`update.downloadAndInstall(cb)` 拆成 `update.download(cb)` → `invoke('shutdown_web_server_for_update')`
→ `update.install()` 三步，顺序钉死（download 之后——下载期间渲染器还要靠 webServer
服务页面；install 之前——Windows 上 install() 内部 `std::process::exit(0)` 之后没有任何
我们的代码会再执行）。`capabilities/default.json` 的 updater 权限从一体化的
`allow-download-and-install` 换成拆开的 `allow-download` + `allow-install`。

**新增分析文档未明确写代码、但推理链条要求补的一段**：mac/Linux 上 `install()` 可能失败
（如签名校验），此时 webServer 已经被我们主动停掉。分析文档 §3 改动 2c 末段提出这个
问题并要求「施工者需确认现有僵尸自愈能否覆盖，覆盖不了就在 catch 里显式重拉」——核实后
`recreate_main_window`（`main.rs:1414` 附近）只在主窗口被销毁重建时触发，不覆盖这个失败
路径，所以在 `catch` 里显式 `relaunch()`，让 Rust 侧 `setup()` 重新拉起 webServer。

### 洞② `terminate_child` Windows 分支无条件强杀

`src-tauri/src/main.rs`：抽出公共尾巴 `wait_then_force_kill(child, graceful_reason)`
（轮询 `try_wait` 直到 `GRACEFUL_SHUTDOWN_TIMEOUT` 超时才 `force_kill`），unix 分支
（先 `libc::kill(SIGTERM)`）和 not(unix) 分支（先 `child.stdin.take()` 关闭管道写端，
触发 webServer.ts 已有的 `process.stdin.on('end')` 自杀监听）都收敛调用它。
`GRACEFUL_SHUTDOWN_TIMEOUT` 维持 3s（未按分析文档 §3 改动 4 的建议改成 5s——见 §3 出入点）。

### 洞③ Node `shutdown()` 关库前的清理步骤无超时

`src/shared/constants/timeouts.ts` 新增 `WEB_SERVER_SHUTDOWN_TIMEOUTS.STEP_MS = 1000`
（分析文档写的 `src/shared/constants.ts` 在本仓库实际是 `src/shared/constants/` 目录+
barrel `index.ts`，按现有 `*_TIMEOUTS` 分组约定放进 `timeouts.ts`，barrel 已导出，见 §3
出入点）。`src/web/webServer.ts` 的 `shutdown()` 给 `durableRunRuntime.shutdown()` 和
`devServerManager.disposeAll()` 各封顶 `withCap()`（`Promise.race` 超时跳过），
`closeAllDatabaseConnections()`（真正 checkpoint + 删 -wal/-shm 的一步）保持不设超时。

## 2. 静态契约断言落地情况（7 条，分析文档 §4.1）

新建 `tests/unit/main/gracefulShutdown.static.test.ts`，7 条全部落地：

   `generate_handler!` 注册 + ACL 白名单同步校验

   按 indexOf 顺序断言，且不再有 `update.downloadAndInstall(`

   不再含 `updater:allow-download-and-install`
6. ✅ 跨端合同：`main.rs` 仍含 `.stdin(Stdio::piped())`，`webServer.ts` 仍在
   `CODE_AGENT_TAURI_BOOT_TOKEN` 守卫块内含 `process.stdin.on('end'`

   `not.toContain('downloadAndInstall')` 被自己写的解释性注释（提到这个 API 名字）
