### 全量 vitest 的两次假红说明（环境噪声，非本单代码问题）

第一次不限并发跑 `npx vitest run`（默认 worker 数）先后崩了两次：
1. 一次 Rolldown/Rust 绑定 panic（`Failed to get current dir: Os { code: 4, kind: Interrupted }`），
   典型的沙盒下多进程互相发信号导致的系统调用中断，与本单代码无关。
2. 一次跑到 30+ 分钟后进程消失、无终态摘要，同一时段本会话内另有 5-6 个兄弟施工 agent
   （t1/t2/t4/t5/t6 系列）在同一台机器上并发跑各自的验证，资源竞争导致本进程被打断
   （协调者随后确认"机器负载管控，串行施工模式"）。

第二次在**协调者确认本单是当前唯一在跑的 agent**后，加 `--maxWorkers=4` 限制并发重跑，一次性完整
跑完、0 failed——与协调者给出的已知基线一致（`capabilityCenterService.test.ts` 等在高负载下的
5-6 个抖动失败，本轮限并发+单跑下全部消失，未在最终结果中出现）。
