## 1. 产品结论

v0.30.0 之后，Neo 的主会话从“一个执行中的聊天线程”收敛为“可以持续派活、追问、转向和停止的指挥台”。文字与实时语音共享后台任务并发、lane 串行、幂等派发和终态回流合同；单个 `spawn_agent` 转入后台后也进入现有成员条、概览和停止入口，不再成为不可见运行。

同时补齐三条用户闭环：composer 上下文按会话/空间/草稿隔离并在新建会话时显式移交；浏览器工作台允许用户导航和直接接管受控页面；会话历史由 SQLite 分页与 FTS 提供完整召回，并能从 UI 或只读 CLI 导出可复核诊断包。

## 2. 已实现行为

### 2.1 会话指挥台

- 前台 brain 的委派工具为 `delegate_task / spawn_agent / steer_task / cancel_task / task_status`；耗时执行由 `SessionCommandCenter` 交给 `TaskManager.startBackgroundTask()`，前台 turn 不再占住整个会话。
  - `delegate_task`（#1055 由 `spawn_task` 改名）承接通用后台任务。改名不是重构：模型从 tool schema 推断能力边界，schema 与提示词冲突时信 schema，而旧名与"写文件"无语义关联，导致前台收到写请求时拒绝服务、从不派活。契约因此写进工具 description，并以「产出什么」命名。
  - `spawn_agent`（#1056 补登记）是**角色委派**入口。此前它不在前台工具面里，用户说「让某角色去做 X」时模型只能用通用后台任务把角色名写进 prompt 扮演，角色从未被真正调起、`RoleWriteBack` 不进。
- 文字与语音共用 `SessionTaskConcurrencyPool`：全局最多 4 件、单会话最多 2 件；同一 `laneKey` 同时只运行 1 件。
- `submissionKey` 是派活幂等键；重复调用返回既有任务。容量已满且调用方未明确允许排队时返回 `requires_choice`，由前台向用户确认，不静默扩容。
- queued 任务可在启动前追加要求或取消；running 任务通过 `TaskManager` 精确 steer/cancel。终态写回会话 system message，并投影到 `BackgroundTaskLedger`。
- `task_status` 的序号只用于当前活跃任务；目标缺失、已终态或歧义时 fail-closed，不回落操作另一件任务。

### 2.2 任务可见性与停止

- 普通单 `spawn_agent` 超过前台预算转后台时，保留 legacy agent 身份和 SpawnGuard 生命周期；`singleSpawnVisibilityRegistry` 只创建短生命周期的 UI scope 映射。
- 该映射复用既有 swarm event 投影，使成员条、Task Workspace Overview 和停止入口显示真实后台状态；完成、失败或取消后删除映射。
- run/agent 取消通过 registry 路由回原 agentId，不把 synthetic UI scope 当执行身份，也不要求不存在的 coordinator。

### 2.3 Composer 上下文分槽

- `ComposerScopeKey` 明确区分 `draft`、`space:<projectId>`、`session:<sessionId>`；工作目录、routing、browser mode、skills/connectors/MCP、团队配方、pin 和专家意图不跨槽串扰。
- 从草稿或空间发起新会话时，`planScopeHandoffToSession()` 把 turn 选择移交到新会话槽；pin 通过 `setSessionPin` 物化，专家通过 session binding 物化，源槽随后清空。
- 已物化的 session pin 以 host 为真源；renderer 的 pending pin 只表示尚未创建 session 的挂载意图。

### 2.4 Browser 工作台与账号态

- Browser tab 提供用户地址栏、后退/前进/刷新、加载中与失败状态；Agent 正在执行时，用户导航先经过交互门，不静默抢写同一页面。
- Phase 3 将 live frame 的点击、输入、按键和滚动经 `UserBrowserLinkService` 送入 owner-aware operation queue；viewport 与 frame 坐标映射在 shared contract 中对账。
- 用户接管和 Agent 执行仍受 Surface Session/Grant/Observation 合同约束。登录、MFA、CAPTCHA、支付与账号安全动作固定转人工。
- Managed Browser 默认使用个人 persistent profile；Cookie 导入要求显式入口和 host approval，只展示域名摘要，不向 UI/日志暴露 cookie value。Relay 仍依赖扩展安装、配对和 tab lease。

### 2.5 会话事实源、搜索与诊断

- `messages.metadata.correlation` 把 session/run/turn/tool call 关联到日志、audit、MCP、sandbox、browser 与 telemetry；SQLite 仍是会话事实源，correlation 只做 join key。
- 诊断包 v2 由 `src/host/session/spine/packageBuilder.ts` 统一生成：transcript、五泳道 ledger、日志时间窗、audit、permission decisions、tool executions、环境指纹和 manifest 同包输出；`shareable` 默认脱敏 home path 和 credential-like 内容。
- `neo session list/timeline/export/digest` 以 readonly SQLite handle 读取同一投影，不启动 Agent，不修改 DB；UI 右键导出复用同一个 package builder。
- 会话搜索接入 `session_messages_fts`。3 字及以上走 FTS5；中文 2 字等短查询在 UI 路径显式回落 `LIKE`。默认过滤 rewound、meta 和 loop 内部消息。
- 侧栏列表使用 SQL `limit/offset` 分页；active/archived/all 三种过滤在 host 查询层成立。静默刷新保持已加载窗口，追加页按 id 去重。

### 2.6 指令记忆写入权威门

- `User Directives` 与普通 `User Memory` 分块注入；directive 只有用户明确确认后才具备指令优先级，普通记忆不提供授权。
- `directiveMemoryPathAuthority` 在 `ToolExecutor` 统一识别写入记忆目录的 Write、Bash 重定向、MemoryWrite 及声明式 path 参数；缺少匹配 fingerprint 的确认 grant 时拒绝执行。
- 规则文件继续采用同目录临时文件、校验、fsync、rename；坏文件进入 `.corrupt-*`，不进入活动记忆集合。

## 3. 架构与事实源

## 4. 当前边界

- `SessionTaskSlotLedger` 是当前进程内并发/队列控制面；任务终态和用户可见回流会落库，但完整 slot 队列本身还不是跨重启调度日志。重启恢复继续以 TaskManager/Durable Run 的既有恢复合同为准。
- 诊断包能证明当时落盘的会话、账本、日志与 audit；它不证明线上 provider、外部 CLI 或浏览器当前仍可用。
- `shareable` 包做规则化脱敏，仍应在对外发送前人工复核；`full-local` 可能含 prompt、命令、路径和敏感信息，不得默认分享。
- Browser personal profile 是 Neo 管理的 persistent profile，不等同于无条件接管用户当前 Chrome；Cookie 导入只解决显式选择的账号态迁移，Relay 的签名分发与升级兼容仍需继续补强。
- FTS/分页解决“历史内容够不到”；它们不改变云同步完整性，也不保证已被本地删除或从未同步的会话可恢复。
- ADR-054 的第三轮阻塞修复已合入源码与自动化门；下一次正式发版仍需以新 tag 的 fresh build、真实文字/语音会话、数据库/日志双信源重新验收，不能用本 spec 代替发布证据。
- 🔴 **写边界在语音派活这条腿上未闭合（2026-08-09 真机 FAIL，缺口仍在 main 上）**：会话没有 Project Source、`working_directory` 是 `$HOME` 时，语音派出的后台 run 把 `$HOME` 判成「写入项目目录内」自动放行、文件真实落盘、审批请求 0 次。文本链路那半已堵（`delegate_task` 前置预检返回 `WORKSPACE_REQUIRED`、任务不创建），语音链路不走该预检。**这不是本批引入的回归**——v0.31.0 的 `createRunContext` 无条件铸 legacy scope、零宽度校验，覆盖面更宽；本批是不完整的修复。定因与判据见 private-archive 的
  `2026-08-09-语音派活-HOME写边界未闭合-安全单.md`。**读本 spec 的人不要把「前台写请求一律走 `delegate_task`」当成写边界已经处处成立。**
