## 2. 关键设计点（详见 ADR-055）

- **牙齿在编译期**：`satisfies Record<ToolArtifactKind, ArtifactRole>`，新增 kind 漏登记 = tsc 报红。
- **`role` 必填**：可选会让「新增分支忘了填」静默漏进产物（fail-open）。改必填时 tsc 当场抓出一个漏填产出点（`TaskWorkspaceOverview` 的 `artifactItems`）。
- **`text` fail-closed / `binary` deliverable**：过程材料是文本形态的；不存在「读出来的二进制产物」。
- **拒绝清单收窄不删**：ToolArtifact 通道改用角色轴；metadata 路径兜底通道（`outputPath` / `metadata.filePath` 等）不经过 artifact，清单在那条路上继续承重，但作用面从「所有工具」收窄到「不产 artifact 的老工具」。

## 3.4 全量测试照出的四处回归（都是本单自己引入的）

红线用例**一条都没抓到这四个**——它们全是我按"想到的形态"造的干净夹具（一个工具产一个
artifact、kind 都在枚举里）。真正照出问题的是**既有测试里带历史包袱的夹具**。

| # | 回归 | 根因 |
|---|---|---|
| ① | 「既写文件又产 artifact」的工具丢掉 `outputPath` 的文件 | 收窄兜底通道时，把「工具声明的产出」（`outputPath`）和「可能是输入的模糊路径」（`metadata.imagePath`）一视同仁 |
| ② | `kind: 'html'` 的 Write 产物蒸发 | 未登记 kind 兜成 material。**方向想反了**：四个 material 类型全是显式登记的，未登记的按定义不可能是过程材料；而 `normalize` 在 kind 缺失时填 `'artifact'`，兜 material = 所有没写 kind 的真产物静默消失 |
| ③ | 只读工具的读取内容重新上屏 | 删 `shouldProjectToolArtifact` 时把里面的只读检查一并删了。**角色轴管「分类」，只读清单管「读取动作要不要上屏」，两件正交的事** |
| ④ | 9 处 `vi.mock` 缺新导出 | 见下 |

②的教训：`fail-closed` 的意图应当由 `text: 'material'` 那一条承担，
**不该靠惩罚未知 kind 来实现**——后者的代价是丢用户的交付物，比多摆一条杂项严重得多。

### `vi.mock` 漏网：手工列模块名必漏

本轮做过一次双 grep（符号名 + 模块路径），但**模块名是手工列的**，漏掉了
`useWorkspacePreviewModel`（hook 模块，与 utils 的 `workspacePreview` 同前缀但是两个文件）。

改成**从改动清单派生**后一次扫全：

```bash
for f in $(git diff --name-only <base> HEAD -- src/ | sed -E 's|^src/||; s|\.tsx?$||'); do
  grep -rln "vi.mock.*${f}['\"]" tests/
done
```

扫出 9 个测试 mock 了该 hook，**其中只有 3 个当时报错**——另外 6 个没渲染概览所以没碰到
缺失的导出，是待爆的雷，一并补齐。

这是「按名字枚举必漏」在本仓的又一次复发，只不过这次枚举的是**模块名**而不是工具名。
**判据要从机器可导出的清单派生，不从脑子里列。**

## 4. 守不住的断言（如实记录）

1. **红线用例测不到产出点是否真设了 role**。它们手写 role 进夹具，测的是消费端分流。
   实测：只有红线用例时，撤掉 `notebookEdit` 的标注照样 19/19 全绿。补静态契约门才守住。
   **两道门是互补的，不能只留一道。**
2. **静态契约门只守清单里已登记的四个产出点**。将来某个 `kind: 'text'` 产出点变成交付物而
   没被加进 `DELIVERABLE_TEXT_PRODUCERS`，这道门不会知道——它守的是「已知该标的没漏标」，
   不是「该标的都被发现了」。零候选 fail-closed 只能防清单被清空，防不了清单不全。
3. **metadata 兜底通道仍靠按名字枚举的清单**。作用面已收窄，但那批不产 artifact 的工具
   新增时依然默认穿透。彻底解法是要求所有工具都产 ToolArtifact，本期不做。
4. **`receipt` 档零产出点零消费**。本期只标语义，没有任何测试能证明它有用；
   下次回看若仍是零，应当删掉。
5. **红线用例守不住「我没想到的形态」**。本单四个回归全部由既有测试照出，红线一条没抓到——
   因为红线夹具是按我脑中的形态造的。这不是补几条红线能修的结构性局限：
   **自造的红线覆盖已知风险，既有测试携带真实数据的形状，两者不可互相替代。**
   推论：任何改动共享判据的单子，「跑全量既有测试」不是走过场，是主要的发现手段。
