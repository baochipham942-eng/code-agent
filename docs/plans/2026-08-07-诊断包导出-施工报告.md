# 诊断包导出 — 施工报告

执行日期：2026-08-07 ｜ worktree：`.claude/worktrees/agent-a7b087dbdbec1a5f2`（分支 `worktree-agent-a7b087dbdbec1a5f2`）

背景：Windows 测试用户反馈"更新后 agent 卡死"，排查暴露三个缺口——① 用户没有便捷的诊断材料导出入口；② 现有会话诊断包 v2（`src/host/session/spine/packageBuilder.ts`）不含 Tauri 壳生命周期文件（boot 诊断/shell events），恰是"更新后故障"最需要的一段；③ 权限档切换失败时 renderer 侧完全静默。本单三个 scope 均已完成。

## Scope A：app 级「导出诊断包」

### 新增/改动文件

- `src/host/diagnostics/appDiagnosticsBundleBuilder.ts`（新增）：`buildAppDiagnosticsBundle()`，产出含 7 类内容的 zip：
  1. 近 7 天 host 日志（`getLogsPath()` 按 mtime 过滤）
  2. Tauri 壳 boot 诊断 + shell events（`desktop-shell/boot-latest.json` + `desktop-shell/events.ndjson`，来自 `resolveDesktopShellLogDir()`）
  3. 近 7 天 audit（`<userData>/audit`，按 mtime 过滤）
  4. `config.sanitized.json`：先按字段名（`key`/`token`/`secret`/`password`/`credential` 子串，大小写不敏感）整段抹除，再叠加 `sanitizePackageValue` 的 home 目录 + 密钥形态正则兜底
  5. `environment.json`：复用 `diagnosticBundleService.gatherEnvFingerprint`
  6. `renderer-cache-manifest.json`：`<userData>/renderer-cache` 递归目录清单，只记 `path`/`bytes`/`mtime`，不拷内容
  7. 可选 `doctor-report.json`：renderer 侧已有的 Doctor 报告随请求带上，避免再跑一次全量体检
  8. `manifest.json`：文件列表 + sha256 + bytes，形状对齐会话包 v2
  - zip 复用会话包 v2 同款 JSZip，未新增依赖。每类内容缺失时静默降级（不阻塞整包导出），`manifest.includes` 如实标记有无。
- `src/host/diagnostics/desktopShellDiagnostics.ts`：新增导出 `resolveDesktopShellLogDir()` + `DESKTOP_SHELL_BOOT_DIAGNOSTICS_FILE`/`DESKTOP_SHELL_EVENTS_FILE` 常量。**关键发现**：Tauri 壳的 `app_data_dir()/logs`（Rust `main.rs` 的 `web_server_log_dir`）与 Node 侧 `getUserDataPath()/logs`（`getLogsPath()`）在生产态是**两个不同目录**——前者由 bundle identifier 派生（`~/Library/Application Support/<identifier>/logs`），后者走 `CODE_AGENT_DATA_DIR`/`~/.code-agent`。两者只有在 Rust 通过 `AGENT_NEO_TAURI_BOOT_DIAGNOSTICS_FILE` env 把真实路径传给 webServer 子进程时才对得上（这也是 `desktopShellDiagnostics.ts` 现有 `bootDiagnosticsPath()` 一直能读对的原因）。`resolveDesktopShellLogDir()` 优先读这个 env（取其 dirname 作为 shell events 的同目录），拿不到时按平台常量兜底：darwin 用 `~/Library/Application Support/<identifier>/logs`，win32 用 `%APPDATA%/<identifier>/logs`；identifier 取 `CODE_AGENT_BUNDLE_ID` env，缺省回退 `PROD_BUNDLE_ID`（`src/shared/devSlot.ts`），未硬编码字面量。
- `src/host/session/spine/packageSanitizer.ts`：新增导出 `redactSensitiveKeyedFields()`——按字段名整段抹除，`sanitizePackageValue` 原有的正则脱敏只认值的"密钥形态"（如 `key: value` 字符串），抓不住形如 `apiKey: "普通字符串"` 这种字段名即敏感标记、值本身不像密钥的情况。
- `src/host/ipc/diagnostics.ipc.ts`：`IPC_DOMAINS.DIAGNOSTICS` 新增 `exportAppBundle` action，接收可选 `{ doctorReport }`，返回 `{ content: base64, suggestedFileName, encoding: 'base64' }`。
- `src/renderer/components/features/settings/tabs/DoctorSettings.tsx`：「导出日志」（原剪贴板复制体检报告 JSON）升级为「导出诊断包」，体检报告随请求带入 zip；点击后调 `exportAppBundle` → `WORKSPACE.saveBinaryToDownloads` → `showItemInFolder`。Doctor 页 actions 区仍是「导出诊断包」+「重新体检」两个按钮，未增未减。
- i18n：`zh/enSettingsModels.ts` 新增 `providerDoctor.exportBundle` + `toast.bundleExportedPath`/`bundleExportFailed`（保留原 `exportLogs`/`toast.copied`/`toast.copyFailed`——`ProviderDoctorDialog.tsx` 仍在用这几个旧键，不能改名删除）。

### 一处偏离任务描述的地方（有意为之）

任务原文让 renderer 侧用「Tauri save dialog」。实测该做法在这个仓库里**不是**既有惯例——`useSidebarRowActions.ts` 的注释写明"webview 另存为对话框在打包态会静默失败"，会话诊断包 v2（`exportSessionDiagnostics`）现有导出走的是 `WORKSPACE.saveBinaryToDownloads`（host 侧直接写 Downloads 文件夹）+ `showItemInFolder`（访达定位），完全绕开 Tauri save dialog。按"查现有导出惯例并复用"的指示，本单 app 级诊断包导出照抄这条已验证可靠的路径，没有引入 Tauri save dialog。

## 遗留项

- Doctor 页的「导出诊断包」按钮目前只在有 `report`（已跑过体检）时展示，与原「导出日志」按钮的可见性条件一致，未改变；若用户从未跑过体检就想导出，仍需先点「开始诊断」。
- `resolveDesktopShellLogDir()` 的平台兜底分支只区分 win32 / 非 win32（等价当前平台矩阵 darwin+win32，产品未支持 Linux 桌面包），不是真的按 `darwin`/`linux` 分别处理；若未来支持 Linux 需要另加分支。
- 未做真机 dogfood 验证（Windows"更新后卡死"这一具体故障复现需要真机环境，超出本单"补齐导出通道"的范围）；本单交付的是材料收集与呈现能力，不改变故障本身的诊断结论。
