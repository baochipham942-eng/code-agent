本文记录 v0.33.0 已发布代码的产品合同和实现边界。事实冲突时，以 tag 内代码、测试和发布证据为准。`v0.33.0` 之后 main 上的 #1258、#1259、#1260 属于发版后修正，不计入本版已发布能力。

## 1. 产品结论

v0.33.0 把 Neo 从“能执行任务”推进到“执行过程可控、可追、可恢复”：

- 模型协议、联网能力和思考能力由 `(provider, model)` 能力矩阵决定，逐轮开关进入真实请求，不再依赖散落判断。
- 每轮执行有增量 trace、结果印章和会话检查器；发射类动作预登记补偿，能力装卸记录依赖与逆操作。
- 语音从单一语音活动检测升级为轮流说话合同，补齐打断证据、半句话等待、重连审批恢复和会话审计。
- 计划先进入可编辑审批卡，批准后再原子同步任务；产物生成过程可在预览区跟随，但用户主动操作始终优先。
- 无人审批的入口、开发槽自动批准和真人审批被分开记账。需要确认但没有审批界面时，默认拒绝并说明真实来源。
- 常驻工具与提示词预算下降约 4.5k token/轮，低频能力改为按需加载；工具可达性、schema 预算和提示词版本均有机器闸。

## 2. 已实现行为

### 2.1 模型能力矩阵与逐轮联网

**合同**

1. `resolveModelCapabilities(provider, modelId)` 是协议、内置搜索、交错思考和兼容字段的统一判定入口。未声明组合回落到 Chat Completions、无内置搜索、无 interleaved thinking，不能从相似模型名推断能力。
2. Responses 是独立协议族。它保留 reasoning、tool call / tool output 配对、同轮 preamble 和上游流式错误原文，不把 Responses 响应强行投影成旧 Chat Completions 形状。
3. 逐轮 `searchEnabled` 随用户真实发送载荷进入 ConversationEnvelope。关闭时不得从编辑、重发或旁路重新打开。
4. 智谱与 MiniMax 是可配置的外部搜索源。凭据缺失、余额不足、限流和网络错误使用结构化失败原因；失败不伪装为空结果。
5. provider、model、价格、上下文窗口和 max tokens 共同参与路由与成本画像。同名模型在不同 provider 下不共享未经验证的能力和价格。

### 2.2 会话 trace、检查器与能力生命周期

**合同**

1. `TurnTraceRecorder` 记录请求清单、模型、工具、权限、结果、补偿和能力生命周期事件。事件在内存中产生后按 8 条或 2 秒先到者增量 append，终态再强制 flush；应用崩溃后允许读到已落盘的轮内前缀。
2. 会话检查器提供轮级概览和事件明细两层视图。进行中的轮从已落盘事件接回 live tail；检查器只展示已经存在的证据，不反向驱动执行。
3. 轮结果印章由 trace 事实投影到 Turn Card 和 Workbench Overview。完成、失败、取消保持各自终态，不用 UI 文案改写执行事实。
4. 能力单元必须声明 namespaced `depends` / `provides`。重复 provider、缺依赖和环在加载前失败；注册中途失败或卸载时按 LIFO 执行 inverse。
5. 发邮件、写文件等发射类动作在进入 handler 前登记补偿；补偿记录是恢复和审计信息，不代表系统已经自动完成业务回滚。

**事实源**

### 2.3 语音轮流说话与审计

**合同**

1. 用户说话优先级高于 Neo 播报。打断判断分为传输层信号、证据层候选和语义出口；证据不足时保持等待，不把短停顿或截断半句当成轮次结束。
2. SAY/DO 一致性门在分类器故障时保持关闭，不能因为判断器异常而把未完成动作说成已完成。
3. renderer 重连后，未完成的审批恢复到当前会话；旧连接的迟到响应不能静默越过新的审批状态。
4. 通话审计从会话菜单进入，按时间展示语音事件、工具和决策证据。录音诊断能力不等于默认保存或对外上传完整录音。
5. meta 派活、steer 和工具轮声明保留审计价值，但不得作为普通用户输入污染下一轮模型上下文。

### 2.4 审批、拒绝来源与写入边界

**合同**

1. `ToolExecutor` 仍是顶层工具审批 chokepoint。PTC、前台文字、语音、CLI 和评测入口不能各自发明放行语义。
2. 需要人工确认但运行环境没有审批界面时，结果为 `no-approval-ui` 并 fail-closed。超时、取消、依赖失效、评测脚本和真人拒绝分别留痕。
3. `devModeAutoApprove` 只在显式 dev 槽和对应开关同时成立时生效，来源记为 `dev-auto-approve`。它不能吞掉被 `forceConfirm` 标记的信任边界审批。
4. exec policy 按 Neo 数据目录隔离，只从真实用户批准学习；一个 dev 槽或数据目录中的批准不能扩散到另一个槽。
5. 并发写入经过 write isolation；浏览器外部内容先过注入扫描；工作区外写入仍需路径权威与审批共同成立。

### 2.5 可编辑计划审批与产物跟随

**合同**

1. `exit_plan_mode` 产生 pending 计划卡后，当前 run 停在审批边界。用户可调整、删除、重排步骤，或给出修改意见；未批准不得开始执行。
2. 批准时将步骤原子替换进 TaskManager，并以隐藏 meta turn 触发执行；修改意见只触发重新规划，不能边改边跑。
3. 产物开始写入后，Preview 可跟随当前会话的文件并节流刷新。用户正在其他工作台视图操作、暂停跟随或切换会话时，自动跟随不得抢焦点。
4. 工具失败时停止刷新并保留失败现场。产物跟随表达“文件正在变化”，不等价于内容已经验收通过。

### 2.6 PTC、回放与停机收尾

**合同**

1. PTC 脚本里的 `tools.X()` 回到同一个 ToolExecutor，复用 schema、权限、路径隔离、账本和补偿，不允许 worker 侧直接绕开执行面。
2. PTC 保留最大步骤、并发、运行时间和 pin 合同；越界在消耗更多模型或执行副作用前失败。
3. Durable replay 记录事件槽和恢复点，恢复后继续使用同一运行身份和已确认事实；重放不能重复提交已完成的外部副作用。
4. 应用退出时，PTY/终端子进程树、MCP、遥测和持久化由真实 owner 收尾，并受总预算限制。关键持久化失败采用 fail-closed，非关键遥测失败保持 best-effort。

**事实源**

### 2.7 长会话阅读、渲染和用户文案

**合同**

1. 长会话滚动时，轮壳保持可测量；重型嵌套内容可以延迟，但不能用固定占位高度替代整轮真实高度。向上阅读、搜索跳转和流式回底是三条独立状态链。
2. 流式 Markdown 按块 memoize，节拍跟随快照 p95；性能优化不能改变历史消息、工具状态或搜索目标的可见性。
3. 中英混排、Mermaid 明暗主题、滚动条窄带和计划图标对齐使用设计系统 token 或明确布局合同。
4. 产物卡和预览区不向用户展示“已验证/未验证”等内部质量口径。真正的验收状态由证据卡或验收流程表达。

## 3. 架构不变量

| 不变量 | 失败时的产品代价 |
|---|---|
| 能力声明必须在请求前消费 | UI 显示可用，模型实际走错协议或烧完 token 才失败 |
| 所有执行入口汇入同一 ToolExecutor | PTC、语音或评测形成权限旁路 |
| 审批来源由处理器自报 | 机器拒绝被记成用户拒绝，无法追责和恢复 |
| trace 是执行投影，不是第二执行器 | 检查器状态与真实任务分叉 |
| 发射类动作先登记补偿 | 外部副作用发生后没有可恢复线索 |
| 计划审批与执行 run 分界 | 用户仍在编辑时任务已经开始 |
| 用户主动工作台操作优先于自动跟随 | Neo 抢焦点，用户失去当前工作上下文 |
| 用户开口优先于语音播报 | 通话继续抢话，控制权归属错误 |

模块关系和状态所有权见 [v0.33 运行时可观测与控制架构](../architecture/v0.33-runtime-observability-control.md)。用户可见状态与交互文案见 [v0.33 用户体验合同](../designs/v0.33-user-experience-contract.md)。

## 4. 数据与兼容性

- v0.33.0 对 v0.32.0 的本地会话、项目和设置保持兼容，无需人工迁移。
- 新增 trace 和审计字段采用向后兼容的 optional / append-only 形态；历史轮次没有新事件时，检查器应显示证据缺席，不能反推失败。
- 模型能力矩阵只影响后续请求，不改写历史会话中已经使用的协议或成本记录。
- shareable/full-local 诊断包的既有脱敏边界保持不变；会话检查器新增可见性不等于可以直接对外分享原始 trace。

## 5. 当前边界

- v0.33.0 没有把所有 capability kind 都迁入可装卸单元；P2 运行时当前只允许 `skill` 单元。
- capability inverse 和 compensation 是可执行恢复钩子与登记，不是跨服务事务，也不保证外部系统一定可逆。
- 逐轮联网开关控制 Neo 是否调用搜索能力，不能约束模型供应商自身的训练数据或平台级留存政策。
- 会话检查器能读取已 flush 的事件前缀，不能从进程崩溃前尚未落盘的内存恢复完整事实。
- 语音自动化覆盖不等于所有设备、麦克风、网络和真实账号场景已经完成发布级真机验收。
- 长会话三门修复随 v0.33.0 发布；tag 后 #1258 和 #1260 对可见性策略与 CI 门的继续收口不属于 v0.33.0 tag。
