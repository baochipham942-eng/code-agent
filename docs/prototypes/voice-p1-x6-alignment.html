接入路径
接入新 Provider 的边界（说明）
  • 轻量接入：与现有 Realtime 事件协议兼容 + Bearer 鉴权时，一份 provider profile（模型、音色、采样率、默认值等非敏感元数据写入 settings）+ Key 按 providerId 隔离进 secure-storage 命名空间 + 真机验收即可。
  • 重量接入：涉及非 Bearer 鉴权方式或新事件协议时，需一次性补 IPC 通道或协议 quirk 适配——不能宣称「绝对零代码」。
  • 当前正式支持仍只有 DashScope 与 OpenAI Realtime 两家；本卡仅说明接入边界，不代表第三家已支持。内置两家继续走既有槽：DashScope = qwen/dashscope，OpenAI Realtime = openai。
本页取舍
  • Key 进 secure-storage，settings 只存非敏感元数据：内置 DashScope 继续既有 qwen/dashscope 槽，OpenAI Realtime 复用既有 openai 槽（与模型配置主 Key 同一把，已拍板）；自定义 Provider 的 Key 按 providerId 隔离进 secure-storage 命名空间，settings 只保留显示名 / Endpoint / 模型 / 音色等非敏感 profile。打码规则沿用前 8 位 + ...，任何状态都不展示真实 Key。
  • 已配态默认收起成「打码值 + 更换」，未配态恒展开输入框——对齐现有 VoiceApiKeyConfig 的形态。
  • 联动是硬回落不是软提醒：换 Provider / 换模型时音色直接落到新白名单第一项，不留「旧音色 + 新模型」的非法组合（正式实现同款策略，见 VoiceModelSettings.persistConversationModel）。
  • 「＋ 添加 Provider」走右侧配置面板：不遮挡主设置区；只有「兼容现有协议 + Bearer」是可配置路径（测试连接成功才允许保存）；选新鉴权/新协议立刻切为「需要代码适配」态并禁用保存，不宣称零代码。取消/关闭不写入任何数据。

麦克风设备选择与系统默认回退

本页取舍
  • 「系统默认」是一个显式选项而不是留空——跟随系统插拔（耳机插上系统自己切）是桌面用户的心智默认。
  • 断开 fail-open：指定设备断开时立刻回系统默认，设置页留常驻提示 + 下拉值就地改回「系统默认」，不静默、不中断通话可用性；用户原选择保留在偏好里。
  • 恢复后自动切回：原设备重新接入后自动切回用户原选择；自动切回失败则继续系统默认，并提示原因，不强迫用户手动改。

口述词表编辑

专名词表注入通话 instructions，纠正转写里的音近/形近错误（如「a点text」→「a.txt」）。清洗规则与 host 侧一致：trim、去重、单条最长 40 字、最多 100 条。

本页取舍
  • 去重是静默的：重复词条不报错、不打断输入流，只给一条轻提示——对齐 host 清洗逻辑（voiceVocabulary.ts 的 seen 集合）。
  • 上限提示在快满时才出现：平时只显示 n / 100 计数，到顶才转琥珀色并禁用添加，避免常态打扰。
  • 超限不截断：超过 40 字的词条整条拒收并说明，不悄悄砍掉尾巴——截断出来的半个词进词表比没有更糟。

状态文案示例（zh / en）与多语言注意点
  • Verified：中文「已核验」 / English「Verified」——有复核证据才允许出现。
  • Unverified：中文「待核验」（完整表述「已结束 · 待核验」放 tooltip/说明位） / English「Unverified」（完整表述「Finished · pending verification」）。
  • 注意点①：正式实现 DeliverableCardList 的 statusMeta 目前把 'Verified' / 'Unverified' / 'Failed' 硬编码为英文，落地时须补 i18n 词条，不要在组件里写死。
  • 注意点②：徽标宽度随语言变化（中文 2~3 字 vs 英文 11 字符），卡片标题与描述已有 truncate，徽标保持 flex-shrink:0 不挤压；中英文混排时以中文为主文案、英文进 tooltip。
  • 注意点③：状态词不做句子拼接（避免语序问题），完整语义放 tooltip 或说明区整句翻译。
本页取舍
  • 主操作就是点卡本身（预览/打开），不再单独占一个图标位；剩余动作全部进「更多」菜单，菜单项带文字，不靠图标猜。
  • Unverified 徽标常驻：状态语义（已结束 · 待核验）比动作更重要，收敛后依然一眼可见；拿不准的状态不显示（对齐 DeliverableCardList 的证据原则）。Verified 与 Unverified 两态同屏展示，便于对照。
  • 归档是高价值动作：在菜单里排第一位并保留青色强调，收敛不等于埋没。

长任务 · 右侧 Workbench「概览」

复刻现有三栏运行态：左侧栏 / 中央会话 / 右侧 Workbench（比例对齐现状截图，右栏 defaultSize 32%）。现有代码有两种各管各的投影：PinnedTodoBar 只显示当前会话已有 TaskPlan 的步骤；后台任务现场归右侧 WorkbenchOverview → TaskPanel/TaskMonitor。本场景的待生成后台任务只放右侧「概览」面板——不在会话框上方镜像 PinnedTodoBar；中央会话列只保留真实现状的消息流与 ChatInput，不新增任务卡。

本页取舍（对齐现有产品结构）
  • 后台任务只放右侧「概览」：任务现场归现有 WorkbenchOverview → TaskPanel/TaskMonitor 卡片；PinnedTodoBar 只服务当前会话已有 TaskPlan 的步骤，不为后台任务在会话框上方镜像一条。会话列只有消息流与 ChatInput，无内联任务卡、无新增 Todo 区。
  • 有活跃任务才自动开右栏：对齐 App.tsx 的按需展开逻辑（hasTaskWorkbenchContent → 打开概览 tab）；任务取消后右栏回到现有空态叙事（「运行中的任务会实时显示在这里」）。
  • 等待只报可证实信息：任务卡只有真实状态 + 已等待时长，无百分比、无预估。读取失败即停止等待：不再计时、不声称任务仍在执行，只说明无法确认任务状态；只给两个动作——「重试读取」（重新进入读取中，读到可证实的运行状态后才恢复已等待时长；只重读、不重派）与「取消任务」。
  • 完成只收敛不重复：任务卡在右栏转为「已完成」；产物卡只在会话流原位置出现一次，右侧 Workbench 不重复产物卡。
  • 通话状态在 composer 内：VoiceChrome 收敛为 composer 内部固定一行（见场景 6），不再悬浮覆盖会话。

为什么必须标注「未验证」
  • DashScope 实测教训（2026-07-26）：session.update 照收、session.updated 原样回显音色，但不受支持的音色直到第一次真合成才 400。回显不是可用性判据。

  • 因此两项能力在 UI 上永远带「探针 / 未验证」徽标，验证通过前不进 release notes、不写进用户文档。
通话状态的位置（已拍板，对齐现有 VoiceChrome / ChatInput）
  • VoiceChrome 收敛为 composer 内部固定一行：不再悬浮覆盖会话；沿用现有圆角（rounded-xl）、边框（zinc-700/70）、底色（zinc-900/80）与字级（11.5px 状态字），只显示「通话中 mm:ss」动态计时。
  • 隐藏非必要信息：专家名（与助手）与通话模型名（qwen3.5-omni-flash-realtime）不进这一行——通话对象就是当前会话，模型名是诊断信息，不占常态 UI。
  • 操作沿用现有 30px icon 按钮语言：静音（mic / mic-off，静音时转琥珀）与挂断（红色 ✕）各一枚 30×30 圆角按钮，不扩大占位；挂断后该行消失，composer 恢复原样，底栏语音按钮可再次发起。
  • composer 本体复刻现有 ChatInput：composer-elevated 圆角 16px 浮起容器 + 底栏（＋ / 请求批准 / 模型 pill / 口述 mic / 语音主按钮），未另造独立 composer。

设计说明 · 方案取舍与未决产品判断

本原型的所有关键取舍汇总，以及需要产品负责人拍板、原型不替做的决定。

方案取舍（已按对齐结论做进原型）

1 · Provider 下拉放在「语音模型」tab

取舍：Provider 是模型配置不是使用偏好，与 Key / 通话模型 / 音色同 tab 收拢；「实时语音」tab 继续只留打断方式、灵敏度等偏好。

代价：两个 tab 的职责边界要靠文案维持（key 的家在语音模型 tab，缺 key 的入口引导只是补救通道）。

2 · Key 进 secure-storage，永不展示真值

取舍：敏感 Key 一律进 secure-storage：内置 DashScope 继续既有 qwen/dashscope 槽，OpenAI Realtime 复用既有 openai 槽（已拍板）；自定义 Provider 按 providerId 隔离进 secure-storage 命名空间，settings 只存非敏感元数据（显示名 / Endpoint / 模型 / 音色等）。已配态只显示前 8 位打码，编辑态空输入框重填，不回显原 Key（正式实现 raw key 不出主进程）。

代价：用户无法「看一眼确认自己贴对了哪把 key」，只能靠打码前缀辨认。

3 · 模型 ↔ 音色强绑定，硬回落

取舍：音色选项只从当前模型白名单出；换模型 / 换 Provider 时音色直接落到合法值，不给非法组合留存的机会。

代价：用户换模型可能没注意到音色被改了——靠音色下方的说明文案兜底。

4 · 麦克风默认跟随系统，断开 fail-open，恢复自动切回

取舍：「系统默认」为显式首选项；指定设备断开时 fail-open 回系统默认并常驻提示；原设备恢复后自动切回原选择，自动切回失败则继续系统默认。

5 · 词表清洗静默化，上限显性化

取舍：去重/限长不打断输入；100 条上限用计数器常态可见、到顶才转为警告态。

6 · 文件卡动作收敛：主操作 + 更多菜单

取舍：点卡 = 主操作（预览/打开），其余动作收进带文字的菜单；状态徽标（尤其 Unverified）不参与收敛。

取舍：状态文案给 zh/en 双语示例（已核验 / Verified、待核验 / Unverified · Finished · pending verification），落地须补 i18n 词条——正式实现 statusMeta 目前硬编码英文。

代价：次级动作从 1 击变 2 击——用「不拥挤、不误触、看得懂」换这一击。

7 · 长任务只放右侧现有「概览」（已拍板）

取舍：后台任务现场归右侧现有 WorkbenchOverview → TaskPanel/TaskMonitor 卡片；有活跃任务时按 App.tsx 的按需展开逻辑自动打开右栏「概览」tab。现有两种投影各管各的：PinnedTodoBar 只显示当前会话已有 TaskPlan 的步骤，不为后台任务在会话框上方镜像一条；不新增右栏 Todo 区。会话主列只保留真实现状的消息流与 ChatInput，无内联任务大卡。

取舍：执行时长不可预测——只展示可证实状态与已等待时长。读取失败即停止等待：不再计时、不声称任务仍在执行，只说明无法确认任务状态；只给「重试读取」（重新进入读取中，读到可证实的运行状态后才恢复已等待时长；只重读不重派）与「取消任务」。完成后产物卡只在会话流原位置出现一次，右侧 Workbench 不重复。

取舍：窄屏时三栏降级为单列堆叠（左栏隐藏、右栏落到会话下方，文档流内，不覆盖输入框）。

8 · 探针能力明示未验证

取舍：音色热切换、上游热词只做交互演示，常驻「探针 / 未验证」徽标与教训说明；验证通过前不对用户承诺。两项操作都门控在「通话中」——通话结束后操作不可用并说明原因。

9 · 接入新 Provider 的边界要说实话

取舍：兼容现有 Realtime 事件协议 + Bearer 鉴权的，一份非敏感 profile 写 settings + Key 按 providerId 隔离进 secure-storage + 真机验收即可；涉及非 Bearer 鉴权 / 不兼容事件协议的，必须一次性补 IPC 通道或协议 quirk——对外表述写「轻量接入 / 重量接入」两档，不宣称绝对零代码。内置 DashScope / OpenAI 仍走既有槽。场景 1 的「＋ 添加 Provider」把这条边界做成了可点击流程（见第 12 条）。

10 · 试听样音不伪造（已拍板）

取舍：仓内没有可靠真实样音，试听一律「待生成」禁用态并标注「真实样音待各 Provider 真上游生成并核验」；禁止用系统 TTS 或合成音冒充 Provider 音色。音色事实：DashScope qwen3.5 真机验证仅 Tina / Ethan / Serena 3 个；OpenAI profile 为 marin 等 10 个官方音色。

11 · VoiceChrome 收进现有 composer 固定一行（已拍板）

取舍：基于现有 ChatInput 的 composer-elevated：VoiceChrome 收敛为 composer 内部固定一行/槽位，沿用现有圆角、边框、字级与按钮语言，只显示「通话中 mm:ss」动态计时；专家名与通话模型名不进这一行；静音/挂断沿用现有 30px icon 按钮，不扩大占位。不另造独立 composer，不悬浮覆盖会话；结束后该行消失，底栏语音按钮可再次发起。

12 · 添加 Provider：可配置 vs 需适配（已拍板边界）

取舍：「＋ 添加 Provider」在右侧配置面板进行，不遮挡主设置区。可配置路径（兼容现有协议 + Bearer）收集 profile 必要字段：显示名、稳定 providerId、Realtime Endpoint、鉴权方式、API Key、模型 ID、音色列表/默认音色、上行采样率。其中非敏感元数据写 settings；API Key 按 providerId 隔离进 secure-storage 命名空间（只掩码不回显）。测试连接成功是保存的唯一闸门（未测试/测试中/失败均禁保存，改字段即作废重测）；保存后进入下拉并切换为当前 Provider，Key 态与模型/音色联动。

取舍：选非 Bearer / 不兼容事件协议时，面板整体切为「需要代码适配」态：说明需补 IPC 通道或协议 quirk，禁用保存，不宣称零代码。取消或关闭不写入任何数据。

Q1 · 音色热切换若上游真合成失败，策略是当场提示还是静默回退旧音色？
原型倾向当场提示（与「回显 ≠ 可用」的教训一致），但提示发生在通话中，打断成本仍待产品拍板。
