# 注意力预算：真实下发五桶分解

日期：2026-08-14

## 结论

本次拿到 3 个可复核的真实 CLI 场景、9 次最终请求体：普通对话 2 轮、goal 2 轮、多 agent 5 轮。三者均使用 APP 默认 `custom-tokenrhythm/deepseek-v4-flash-0731`，走 Responses 协议。语音没有可复用的真机请求留痕，保持缺口，不用模板补数。

首轮注意力成本主要由静态系统提示与工具 schema 构成：普通场景分别占 44.8% / 45.3%，goal 为 48.4% / 50.6%，多 agent 为 49.2% / 49.6%。普通第二轮因 `Read` 返回整份 `package.json`，历史消息涨到 31.5%。工具 schema Top3 为 `TaskManager 2502`、`WebSearch 1233`、`Grep 855` token。

## 口径与证据边界

- 抓取点是 provider 转换完成后的最终发送边界：chat-completions 为 `AiSdkAdapter → makeAiSdkFetch`，Responses 为 `ResponsesProvider → electronFetch`。每个文件保留最终 `payload`，并镜像 `messages` / `tools` 便于离线分析。
- 五桶只统计最终 `messages + tools`：JSON 序列化字符数 ÷ 3，四舍五入。工具桶严格取每个工具的 `name + description + parameters`。model、stream、store 等协议控制字段不入桶。
- 静态系统提示取首个 system message；后续 system message按来源分为运行时注入与 nudge；其余 user / assistant reasoning / function_call / function_call_output 均归历史消息。
- provider `inputTokens` 来自真实 `model_call` usage。缓存命中轮出现 157 / 107 这类低值，说明它不是完整请求体体积账本，故与字符估算并列、不互相替代。
- 原始 dump 位于 `/tmp/l8-att1-normal.P8vU04`、`/tmp/l8-att1-goal.y7641n`、`/tmp/l8-att1-multi.blX6xJ`，含本机路径与用户输入，不进仓库。

证据档位：真实最终请求体 + provider usage 为 A；源码定位、全景表对账与静态棘轮为 B；语音为缺口。
